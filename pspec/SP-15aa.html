Two or more fully independent Podium instances must run concurrently on one machine. Every instance has explicit identity and non-colliding state and install roots, network endpoints, CLI and session routing, agent runtime and session ownership, and supervision and service identities.

Operator documentation and runtime acceptance proof must demonstrate that one instance cannot read, mutate, stop, update, or route commands into another unless sharing is explicitly configured.

Decision record: instance identity is decided by docs/adr/0001-authority-ownership.md D5 and amended by docs/adr/0001-authority-ownership-amendment-2.md (ADR 1 Amendment 2, POD-733): D16 the four identity axes (instance / machine / process role / user); D17 InstanceId stays a brand but is a configuration type, never a field on a table, projection or payload; D18 no instance_id column — isolation is by separate state DB, composed with the machine row's owner and grants; D19 deployment-substrate, human-minted at deploy time; D20 zero protocol presence, permanently; D21 cross-instance federation, cross-instance sharing and cross-instance identity portability are OUT — note that "sharing" in the multi-user product means sharing between USERS inside one instance, which this spec's exclusion does not cover and does not permit.
