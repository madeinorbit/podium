Every interactive harness, headless harness, and shell session started by the local macOS desktop backend must be able to run the podium command from that same desktop distribution.

The macOS app passes the exact path of its bundled, signed podium executable to its backend as a Podium-owned environment value. One shared daemon environment builder, used by both interactive and headless launches, unconditionally places that executable's directory first in each managed process's command search path. The Podium-owned entry is above recovered user paths and harness- or account-provided environment values, is never derived from them, and cannot be overridden by them.

This is global session-launch behavior, not behavior in individual harness adapters. Commands started by a harness inherit the managed environment. The bundled executable remains inside the signed app; it is not copied out of the app bundle.

The managed path is private to processes Podium starts. Installing or launching the desktop app does not change the user's shell profiles or terminal command path; exposing podium in the user's own terminal requires a separate, explicit installation action.
