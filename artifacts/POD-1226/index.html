The spine is one line, and every row is one line

Three defects were filed against the flight deck: a rail that did not line up, and a roster whose rows reflowed in a way that read as arbitrary. All three turned out to be the same mistake made in two places — a decision taken per element instead of per column.

The gutter

Four devices in ten pixels, two of them on the icon

An agent row has no left padding — it opens onto its rail — so the 2px amber rule that meant “this one is asking” was painted exactly where the 20px agent tile starts. It crossed the tile's rounded corner, and once a row wrapped to two lines it ran the full height as a bar into empty space. The amber elbow arriving from the left made the same colour say two things at once.

Attention is a tick in the gutter everywhere else in this column. The row wears the same one now, on the same side, at the same offset a task strip uses — and the elbow goes back to carrying provenance alone.

  • attention, outside the rail
  • the branch rail
  • selection, flush against the row
  • the agent tile, untouched
The rail

One rail object, five segments

The header's descent, the view bar, the search bar and the list's top pad each drew their own w-px bg-hairline-soft, while the rows below them drew railFor(leadTone(root)) — 2px in the mission's accent whenever the mission has a coordinator. Same left edge, different width, different ink: the line stepped a pixel wider and changed colour at the first agent row, which is precisely where the design says it must read as unbroken. The rail is resolved once now and every segment is drawn from it, so a jog cannot return without editing that one line.

The roster

The column decides the columns, not each row

The four cells right of the name are a mission-wide table, but the query container was each row — so a row hung under a task, 16px narrower per level of nesting, shed a column its shallower sibling kept. At a 440px deck the two root rows were 28px tall and the three rows below them 45px, giving one list three right-hand edges. Meanwhile the role cell was held open whether or not anything was in it, so a name was cut to JSON pa… with a hundred pixels of nothing beside it.

The ladder

One rung, and it is arithmetic

448px
The deck width at which a row can still seat a fourth cell and print a 120px name: 24 indent + 8 list pad + 8 row pad + avatar 20 + 4 gaps + ref 68 + role 96 + state 80. Below it the role column closes and the asking row hands back its elapsed; above it both return. Both row kinds land on exactly 120px there, which is what makes it one decision rather than two thresholds near each other.

What it costs

Two facts stop being printed on a narrow deck

  • The role word below a 448px deck. For the roles that carry weight it is already said three other ways — the branch runs in the mission's accent, the lead's own elbow is the only one drawn in that accent, and the mission's coordinator is the single agent row with a fill.
  • The elapsed on an asking row below the same rung. Needs you alone measures 76px and fits the column; the stamp is staleness, not the obligation.
  • Both are on the row's own tooltip, which the row did not have before — the four cells were assumed always to fit, and that assumption is what the ladder replaces.
  • The header band still wraps at 300px, putting Add agent on its own line. That one is a deliberate, documented choice (spend a line rather than crush the gauge or drop the word) and was left alone.
