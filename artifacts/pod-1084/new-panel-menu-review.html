The search field did not move. It stays inside the Resume region and keeps its autofocus on open — that was a deliberate behaviour decision and this pass is a re-skin, not a re-plan.

What changed, and why

01 · SURFACE

The panel was one tier too low

It sat on --popover (#23262d) — the same tone as the stage sheet it floats over — under shadow-md, which is a resting shadow. The house panel is the raised chip over a real seam, under the one transient lift the system reserves for things that will disappear.

SURFACE
#23262d → #252830
EDGE
ring foreground/10 → 1px #3a3f48
LIFT
shadow-md → --shadow-popover
RADIUS
6px → 10px (tray)

02 · TYPE

14px rows in a 12px shell

Stock text-sm made every row of this menu a point and a half larger than the identical row in the session menu beside it. The preset's 11.5px is the size the rest of the overlay family is set in.

ROW
14px → 11.5px
PAD
4/6px → 4.5/5px
WIDTH
224px → 248px

03 · VOICE

Section headings were invented here

Recent files and Resume were 11px Geist Sans small caps at muted-foreground/70 — a label recipe that exists nowhere else in the app, and Sans where the system speaks Mono. MENU_SECTION is mono micro-caps in Label Grey and carries the hairline that makes a region read as a region; the anonymous gaps between the four groups are now named rules.

WAS
Recent files · Sans 11px
NOW
RECENT FILES · Mono 10.5px / .12em, over a rule

04 · ALIGNMENT

Three text columns in one menu

Agent rows were indented by a 16px icon, file rows by a 13px one, and resume rows by the literal character ↻ typed into the label — which sits on the baseline at the body font's weight and lands nowhere near either. Every glyph is now 14px on one column, and the resume arrow is a drawn icon like its neighbours.

GLYPH
16 / 13 / “↻” → 14px, one column
ALIGN
items-baseline → items-center

05 · MACHINE VOICE

Timestamps were prose

12m and 2h are the system talking about itself, so they take Geist Mono at micro scale in Faint ink — MENU_HINT, the same trailing slot the session menu states a handoff refusal in — with tabular-nums so a ticking list does not shuffle sideways.

WAS
Sans 11px, muted/70
NOW
Mono 10.5px, faint, tabular

06 · KEYBOARD

Arrow keys lit a different colour than the mouse

Base UI moves real DOM focus onto the highlighted row, so the stock focus:bg-accent fired on arrow-key navigation while the preset's hover: fired under the pointer. The bridge restates focus: and the submenu's held data-popup-open: state, so one row reads one way.

KEYBOARD
#2a2d33 accent → #24272d
POINTER
#24272d (unchanged)

07 · REFUSALS

A refusal that only a mouse could read

An offline machine and a capability-blocked agent dimmed to 50% and explained themselves in a tooltip — the one affordance a touch pointer never opens, on the one kind of row that is declining to respond. Each now states its short reason inline, the way the sidebar's new-agent menu already does, and keeps the sentence on hover.

ADDED
offline · no access · not installed · no host

08 · STRUCTURE

Two copies of the Resume region

The single-machine and multi-machine panels each carried a byte-identical copy of the heading, the field, the empty state and the hit rows — which is how their headings drifted apart to begin with. One ResumeSection, one HistoryItem, three call sites. Net −55 lines.

HEADER
+ NEW PANEL · target checkout

09 · UNCHANGED

Everything the menu does

No row was added, removed or reordered, and nothing about what a click starts moved. The capability gates, the machine resolution, the sibling-worktree filter on the history search, the modal={false} that keeps the mobile keyboard pinned, and the autofocus on open are all exactly as they were.
