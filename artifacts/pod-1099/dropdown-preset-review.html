POD-1099 · Review sheet

Every dropdown in the app, in the house vocabulary

Twenty-two menus across ten files still opened in the look POD-380 retired. Rather than dressing each one, the preset moved into components/ui/dropdown-menu itself — so the two opt-in bridge constants POD-1084 added are gone, and the next dropdown anyone writes is in the family without doing anything.

Why the primitive and not the call sites

Both routes touch the same ten feature files — the primitive has no other callers — so route (b) was never the wider blast radius. What decided it is reach and recurrence. The bridge pair could only dress a panel and a row; a checkbox item, a radio item, a group label, a separator and a shortcut had no bridge at all, and the Display menu is made almost entirely of those. And an opt-in look is one every new menu starts out failing. Two of the twenty-two surfaces now need no local code whatsoever (FlightDeck, IssueSessionsBlock) — they were already correct markup wearing the wrong skin.

Part by part

PrimitiveWasIs
Content bg-popover, rounded-lg, shadow-md, a ring-foreground/10 hairline, p-1 bg-chip over a border-strong seam, rounded-tray, --shadow-popover, p-[6px]. The ring is not overridden — it is gone, because a border can never win against one.
Item 14px rows, focus:bg-accent only The house row: 11.5px, hairline-soft wash lifting ink to text-strong, stated for hover: and focus: so pointer and arrow keys light a row the same colour.
SubTrigger accent slab while held; a full 16px chevron on the text column Same row and held state as everything else; a 12px chevron in faint ink — an affordance, not a second glyph competing with the row's own.
Checkbox / Radio No bridge existed. Stock 14px rows in every menu that used them. The same row as an item, with the indicator gutter narrowed to the new scale.
GroupLabel Geist Sans 12px medium in muted grey Mono micro-caps in --label, per DESIGN.md's Machine Voice Rule — the same section voice the picker and the session menu already use. Uppercased in the primitive, since some headings are data.
Separator Full-bleed bg-border MENU_RULE — an inset hairline, so a rule reads as a pause between regions rather than a cut across the panel.
Shortcut Widened Sans in muted grey MENU_HINT: a keystroke is machine voice, like a timestamp or a refusal reason.
Glyph default [&_svg:not([class*='size-'])]:size-4 — every un-classed icon silently 16px, whatever its size={n} prop said 14px, the house text column. A glyph that must be smaller — a status dot, a lock — says so with a size- class, the one thing the rule yields to.

Where it landed

Surfaces 22

  • NewAgentMenu — the sidebar spawn row. It draws its agent kinds from the menu POD-1084 restyled, and the two no longer disagree. Its lock and status dot keep their own sizes explicitly.
  • IssuesFilters — nine of the twenty-two: the anchored property menu, the Filter menu with six submenus, and the Display menu, which is where the checkbox/radio/label gap showed.
  • IssueCompactControls — rendered both looks in one file. The placement panel drops the hand-applied preset it opted into; its sibling stage menu simply inherits.
  • IssueDetailHeader, DateProperty, PropertyMenu, AgentPanel, ConciergeButton — trailing values moved to MENU_HINT; the two type-ahead fields are carved into the panel rather than raised on it.
  • FlightDeck, IssueSessionsBlock — no local change at all.

Also swept

  • SnoozeControl — a hand-rolled portal menu, not a dropdown, and so not on the list. It opens a pixel from the session menu in the same header and was the last stock-token popup left there.
Left alone. The width overrides (w-56 … w-40, max-h-64) were sized against 14px rows and are now roomier than their contents need. Smaller text in the same box cannot overflow, so none of them break; tightening them would be a second judgment call per menu against data-driven labels — repo names, assignees, issue refs — and is deferred rather than guessed at here.
