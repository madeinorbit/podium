Queues, without the dead lanes

The right dock pins two lanes forever and hides every other one. Merge stays fixed, because it is the only lane with a future to show. Everything else goes fully dynamic, including test:heavy, and the panel finally says out loud what it shows, what it will show, and what just left.

POD-1076 · concept · right dock @ 316px

What is wrong today

The panel does not list queues. It renders live advisory-lock state, and lock names are free-form, created on demand by podium lock acquire <name>. There is no registry to enumerate, so merge:main and test:heavy are hard-pinned in queueGroups() and every other lane appears only while somebody holds it.

  • The heavy lane squats. It holds a permanent three-section block (HOLDING, NEXT UP, READY) that is empty almost all the time now that focused test lanes run lock-free.
  • Real lanes are invisible. validation:watch, podium:dev-bundle, migrations, hotfile:* exist and never show while free.
  • Nothing explains the rule. A quiet panel is indistinguishable from a broken one, so an absent lane reads as a missing feature.

The redesign

RegionTodayProposed
Merge queue Pinned, three sections, always mounted. Unchanged and still fixed. It is the one lane that is meaningful while free, because READY lists branches waiting to enter it. A forward-looking queue earns a permanent seat.
Heavy test queue Pinned beside merge, usually empty. Unpinned. It becomes an ordinary lane that appears while held, keeping its flask icon and TESTING NOW vocabulary through lockGroupKind(). Nothing is lost; it stops occupying a third of the panel to say nothing.
Every other lane Appears while held, unexplained, below the fold. One LIVE LANES band with a standing one-line explainer, a teaching empty state, and a RECENTLY RELEASED tail.
Header count N held, true but reading as a total. N live next to the refresh control, and the band's own count carries the rest.

The rule the panel now states

A row means a real lease. Lanes are created on demand, so a lane exists here while a session holds it and leaves when the lease is released. Nothing is listed speculatively, which is exactly why the absence has to be narrated rather than guessed at.

  • Standing explainer. One sentence under the LIVE LANES header, always present, in the operator's language rather than a dismissible tip. It survives the panel being busy, which is when a newcomer actually looks.
  • Teaching empty state. When nothing is held, the band names the mechanic and the lane names this repo's agents actually take — so "what will show" is concrete, not a promise.
  • Recently released. The client remembers lanes it watched disappear and keeps them for 30 minutes as dim, past-tense, motionless rows. That is the piece that makes the mechanic self-evident: you see a lane arrive, run, and fade, instead of only ever seeing a panel that is already empty. It is client-side memory of real readings: it invents no server state, and it decays on its own.
  • Motion stays honest. Only a lease held right now spins; a released row is completely still, which is what stillness means everywhere else in the shell.

The panel

Rendered at the dock's 316px default, in every state the panel can resolve to.

Why the stale state stops the clocks

A lease countdown that keeps ticking off a reading the client can no longer trust is the panel lying politely. When the query fails, the timers go to CLOCK STOPPED and the live band says plainly that it is no longer tracking. Stillness is the shell's "something needs you" signal everywhere else; it should mean it here too.

What changes in code

  • merge-queue-model.ts: queueGroups() drops the pinned heavy member and returns { merge, lanes }. test:heavy falls through to the same dynamic path every other lock takes, and lockGroupKind() plus lockGroupTitle() are unchanged, so it keeps its flask and its TESTING NOW label.
  • New: a small released-lane memory beside useRepoLocks. Diff each reading against the last, stamp what vanished, expire at 30 minutes. Client-side only; no protocol change, no server work.
  • MergeQueuePanel.tsx: the merge group renders as it does now. The heavy group's bespoke ready copy is deleted. A new LiveLanes section owns the explainer, the lane list, the teaching empty state and the released tail.
  • Known lane names in the empty state come from a short constant, not a registry. They are examples that teach, never rows, so the "a row means a real lease" rule holds without exception.
  • Tests: MergeQueuePanel.test.tsx gains the quiet state, the released decay, and heavy-as-dynamic; the pinned-heavy assertions go.
