Cancelled and duplicate, as real statuses

The tracker stored lifecycle state in two fields — stage and closedReason — and every status control joined them itself, slightly differently. This is one vocabulary of ten statuses, one label table, and one Linear-shaped menu that every surface renders.

The question you asked

Yes — wontfix was our cancelled. Same meaning: work we deliberately are not doing. It is now spelled cancelled, and rows already stored under the old word read back as Cancelled everywhere, forever. Nothing needs migrating.

Duplicate is not the same as cancelled — it is its own ending, the way Linear treats it: both mean "this work will not happen here", but duplicate says the work is tracked somewhere else. It gets its own word, its own glyph, and its own entry in the menu. The existing "Duplicate of…" relation still exists and is the stronger statement — it names the canonical issue. Picking the status is the judgement you make before, or without, finding it.

A fourth ending, superseded, already existed and is set by supersede <old> <new>. It renders in the new vocabulary but is deliberately not in the picker: it needs a target issue, so it belongs to the relations menu.

How Linear does it

Linear has no "closed". It has five categories — Backlog, Unstarted, Started, Completed, Canceled — and a team's named states each live in one of them. Duplicate is a state in the Canceled category, not a fourth thing. The picker is a flat list ordered by category with no headings; the icons carry the grouping.

The part worth stealing is that Completed and Canceled are kept apart on purpose. "We finished it" and "we are not doing it" are different answers, and one word over both destroys the distinction for every count, filter and chart downstream. An earlier cut of this work put Done, Cancelled and Duplicate under one Closed heading — exactly the fusion Linear avoids. That heading is gone. The glyph family

The open ramp is unchanged. What is new is that the cancelled family is muted, never green: success is the colour of work that landed, and an issue closed as cancelled or duplicate did not land. That was the sharpest part of the old problem — the sidebar could not tell "we did it" from "we decided not to".

Where it lands

Every status control now renders the same list from the same place in the model.

  • Right-sidebar issue panel — the dock's status pill and its menu (the one you asked about).
  • Full issue page — the Status property, with a "Closed" heading over the endings.
  • Board / sidebar right-click and the command palette — "Set stage" plus two "Close (…)" actions became one Set status submenu.
  • Phone — the task Status sheet, each ending carrying a one-line hint.
  • Board filters — the status axis now filters by Cancelled and Duplicate; "Done" stops meaning "anything on the done lane". The old open/closed/ready/blocked axis is renamed State so the two stop competing for one word.
  • Folded rows — the sidebar and the phone's work list both said won't fix in their own spelling; both now say cancelled.
  • Activity feed — an event logged years ago as wontfix reads back "closed (cancelled)".
  • CLI — podium issue close --reason done|cancelled|duplicate|superseded. wontfix still works and stores cancelled.

One inherited inconsistency, unchanged by this work and worth knowing: the close-guard dialog runs on the issue page and the issue panel, which pass a handler for it. The board sidebar and the flight deck right-click menu close immediately instead. That fork predates this issue — the old "Close (done)" / "Close (wontfix)" actions behaved the same way — and is filed separately rather than widened here.

Two smaller corrections that came with it

  • The explorer's end buckets are now Done and Cancelled, keyed on status rather than stage. Every ending parks on the done lane, so the old single tab counted cancelled rows as completed work.
  • Bulk status and the phone's deck card offer the whole list, endings included — marking a batch Done needs no extra justification. What changed is that they now run a real close so the ending is recorded; they used to write a bare stage: done patch, which left the rows closed with closedReason empty and folded as a flat "closed".
