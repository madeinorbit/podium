Review state on vacated work

POD-1158 shipped, merged, and handed its leftovers to POD-1192. The board renders that as amber, forever — because review is a stage the agent sets, the UI prints it as an ask aimed at the operator, and nothing in the product can answer it. An attention state with no exit is a permanent alarm, and the operator learns to stop seeing amber.

03 The verdict bar

Today the only review controls in the product are the agent’s podium offer buttons — and an offer is consumed by the next turn in either direction. So a review can outlive every control that could ever end it. The stage must carry its own, derived from the stage, always present.

One sentence of situation, the agenda that makes the call possible, and an exit. Close it out is the recommended verb because the state is resolvable; on a review with unmerged commits the primary becomes Merge · 2, and on one with a live agent the bar does not render at all. Send back… takes a note and re-prompts — or spawns a session if none remains — which is the native version of what --action-input already does in an offer.

04 One vocabulary, five states

The rule underneath all of it: the row states what is being asked and what would end it. Amber is never spent on a state the operator cannot resolve from that row.

05 What it takes

1

Continuation outranks the review labelsmall

isVacatedOrigin() already computes “sessionless, and the work carried on in a started spin-off”. issuePendingDecision() never asks it, so a vacated origin still returns 'review' and burns attention. Teach the decision to return null there, and let the row’s continuation line take the slot it already knows how to render.

packages/client-core/src/viewmodels/mission.ts:449 — isVacatedOrigin packages/client-core/src/viewmodels/slices/issues.ts:306 — issuePendingDecision apps/web/src/features/worklist/UnifiedIssueRow.tsx:252 — flip the ternary
2

A standing verdict bar for the review stagethe real work

Derived from stage === 'review', not from a session offer, so it survives every turn and every reload. Primary verb chosen by the same predicate that picks the row’s words: Merge when there are commits, Close it out when the work is elsewhere, Accept & close otherwise. This is the piece that makes the amber finite.

apps/web/src/app/FlightDeck.tsx — above the spine, beside WhereTheWorkWent
3

The review gets an agendasmall

Open todos, parked/deferred items and the git verdict are already on the issue and already rendered elsewhere. Lifting the open ones next to the buttons is what turns “needs review” from a mood into a list — and gives Accept & close an honest confirmation when a todo is still open.

4

The stamp says mergedtiny

deriveGitStamp computes merged and the sidebar density renders only dirty and ahead — so the row keeps the alarming number and drops the reassuring one. And when the issue record carries no branch, a leftover worktree’s dirt is not this task’s: suppress it, or name it once as a stale worktree with a cleanup action.

apps/web/src/components/GitStamp.tsx:57–60 — stamp density packages/client-core/src/viewmodels/git-stamp.ts:89 — merged is already there
5

The header names the object, not the asktiny

POD-1158 review and CONTINUED IN POD-1192 are two answers to one question, printed eight pixels apart. Keep the later one in the header; the ask belongs in the bar below, where it has buttons.
