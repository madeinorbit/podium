POD-679

Starting discovered work

concept · flight deck + sidebar

The start click is the triage moment

An agent that discovers work already decides whether it is part of this mission (a sub-issue the origin cannot ship without) or its own thing (a spin-off with a discovered-from edge). That decision is made silently, in a CLI litmus test the operator never sees — and then the operator's Start click inherits it blind.

Worse, both outcomes look identical on screen: a started spin-off is still pulled into the origin's spine, because mission membership follows startedBySession and never checks for a spin-off edge. So the origin never looks finished, and the new work never feels like its own.

The fix is one question, asked once, at the only moment the operator has the context to answer it: does this belong to the mission, or does it leave?

2 · The move

The proposal says its shape; the start control asks you to confirm it

Two changes to a moment that today is a single unlabelled button. First, the proposal strip carries one extra word — the agent's own call, in the operator's language. Second, Start becomes a two-way control whose options are phrased as consequences for the mission, not as tracker vocabulary.

3 · After

It leaves the spine, lands in the sidebar, and releases the mission

Departure is visible, not silent: the origin keeps a one-line tick where the work used to hang, so the provenance survives a scroll and a week. But the tick is not a task — no state mark, no seat, no weight in the progress well.

4 · What it touches

Four changes, in rough order of value

  • A spin-off is never a mission member. missionIssueIds (packages/client-core/src/viewmodels/mission.ts:129) adds any issue whose startedBySession is a mission session, with no check for a discovered-from edge — and issues.create stamps that field on every agent create. So today a spin-off is always pulled back in; the existing test passes only because its fixture leaves startedBySession unset. Making the edge win is the single highest-value line here: without it, nothing else can release the origin.
  • The shape word on the proposal strip. One chip on an existing channel (IssueNoteChip) — ↳ part of this mission or ↗ on its own. No new colour; the strip already runs a ⤷ discovered from chip in that slot.
  • The split Start. Menu with the two outcomes; the non-default one runs the conversion server-side in one mutation (drop/park parentId ⇄ add discovered-from), then starts. The same two items stay on the started issue's menu as Move out of this mission / Move into this mission, so a wrong call is one click to undo rather than tracker surgery.
  • The departure tick and the release. A non-task row under the origin, excluded from missionProgress, plus the honest close sentence when everything remaining has left. Proposals never enter the sidebar — the operator ruled that out for column 1 (SidebarUnified.flat-rows.test.tsx) — they enter it only once started as their own thing, which is exactly the distinction this concept adds.
