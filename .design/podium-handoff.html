RResponsive — the repo's mobile concept (single 768px breakpoint, separate MobileApp shell) carried over to the final design: Home list (2a), Workspace + panel dropdown (2b), Superagent overlay (2c)
★Responsive notes for Claude Code — how the old layout did it (apps/web) and how it maps to the new design
1 · One breakpoint, two shells
The repo uses a single 768px breakpoint (lib/hooks/use-is-mobile.ts, matchMedia('(max-width: 768px)')). Below it, AppShell.tsx renders a completely separate MobileApp.tsx — never a squeezed desktop. Keep that: the desktop layout (1a/1b) is columns; mobile is one pane at a time.
2 · Desktop degrades by folding, not scaling
Above 768px the shell flexes via collapsible/resizable columns, not media queries: Super-agent column 320–860px (default 460, collapsible via ✦), right dock 280–860 (default 340, one panel at a time from the rail), sidebar resizable. On narrow desktops you close columns — the engraved column and native pane never shrink below readable.
3 · Mobile header = nav + context
44px header (+ safe-area top): three bordered icon cells — Home, ✦ Super agent (toggle), Issues — then ONE dropdown for the selected issue (the context), then “+” (new agent), then compact host dot. In the new design the dropdown carries the issue's ID square, so the context colour reaches the header.
4 · Panel dropdown replaces the tab bar
The native pane's tabs become the header dropdown: it drops OVER the content (overlay, max-height ~70vh, scrolls; opening it closes the “+” menu and vice-versa — repo #97). Rows = the issue's agents + open files, each with status (spinner / amber count), pin, kill. Rows reuse the desktop tab colours.
5 · Super agent = full-screen overlay
On mobile the engraved column becomes an overlay (absolute inset-0) toggled by the header ✦ — Tray on top (issue-scoped, only actionable items, same empty state as 1c), Super agent chat below. The right rail's Issue/Git/Files/Shell fold into the panel dropdown + issue page on mobile.
6 · Keyboard & viewport
Copy the repo's useVisualViewportHeight trick verbatim: pin the shell to --viewport-h (visualViewport), snap document scroll back to 0, flag --kb-open when the soft keyboard eats >150px so the key bar drops its safe-area padding and sits flush above the keyboard. Terminal key bar (esc/tab/arrows/⏎) is bottom-anchored.

★Build notes for Claude Code — read before implementing; 1a/1b are the reference screens, 1c the empty state, 1d the live motion spec
1 · Anatomy
Top bar 44px (logo podium-logo.svg, nav, machine + quota meters). Left: Work sidebar 262px, issues grouped by project (LUMENFALL / TARTLET, mono 8.5px labels). Middle: the engraved column — darker surface (#0a0a0e) with inset shadows on top/left/right — holding Tray + Super agent. Right of it: Native agents pane (tabs, Claude Code session, terminal, prompt). Far right: 44px rail (Issue / Git / Files / Shell), expandable.
2 · Context flow
The selected issue's colour flows through everything downstream: selected row + bridge notch out of the sidebar → faint radial glow at the top of the engraved column → tray cards → native tab bar + chrome → right rail gradient + its ID square. Always mixed, never flat: color-mix(in srgb, ISSUE n%, BASE) at 8–28%. Uncoloured issues run the identical mechanics in slate #94a3b8 (see 1b). The Super agent area itself stays neutral — only the glow behind it and the tray items carry the colour.
3 · ID squares
Linear-style IDs (POD-128) rendered as 26px rounded squares, Geist Mono 6.5px, two stacked lines (POD / 128). Language: solid colour fill = coloured issue · solid grey border on #25252f = active but uncoloured · dashed border = queued/idle (dimmed, opacity .65). The same square repeats identically in the sidebar, Tray header, CTX badge, and rail — it IS the issue's identity everywhere.
4 · Motion rules
Permanent animation ONLY while an agent is computing: braille spinner ⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏ (CSS content keyframes, .8s steps) + the timer counting up, both mono + green #10b981. Every phase change is one single one-shot morph (.4–.9s): amber row flash, badge pop-in, ignite scale on start, ✓ pop on done — then total stillness; stillness is the “needs you” signal. The timer anchors every morph: green counting → freezes and flips to amber “2m ago” → grey total ∑. Rail corner badges: green spinner = computing, amber numbered = waiting count, ✓ = done.
5 · Type & colour
Geist (UI) / Geist Mono (IDs, timers, terminal, section labels). Surfaces: bg #0e0e12 · panels #16161c · engraved #0a0a0e · hairlines #2a2a34 / #25252f. Text #f3f3f8 / #d7d7e0, muted #9a9aa8 / #6c6c78. Semantics: attention #f59e0b (amber = “waiting on you”, everywhere) · working #10b981 · Claude #D97757 · neutral flow #94a3b8. Issue palette samples: #8b5cf6, #f43f5e, #14b8a6. Wordmark is white, ~15px tall in the top bar.
6 · Tray & Super agent
Tray (▤, top of engraved column): scoped to the selected issue, shows ONLY items needing a human — reviews with actions, questions with answer chips. Never shows working/status rows; when nothing needs you it collapses to one quiet line (1c). Super agent (✦, header “OVERARCHING · KNOWS THIS ISSUE”): one chat across all issues — feed shows cross-project events — answering with the selected issue as context (CTX). Both headers share the same compact bar style (#08080c, hairline top+bottom).
