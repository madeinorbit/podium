POD-127 · DESIGN PROPOSAL · SETTINGS · 2026-07-21

Settings, made instrument-grade

The settings surface is the last major pane that predates the Superade system: a flat 17-item nav, controls flung to the viewport edge, prose interrupting rows, and a permanent Save footer. This proposal regroups the IA, rebuilds the layout on the carved-navy grammar, and makes saving honest — without touching the section components' logic.

What's wrong today

F1
Flat 17-item nav with no grouping.

Agents-config, connections, infrastructure, and app preferences interleave in one list. Finding "Hibernation" or "Background LLM" means reading all 17 labels; the list scrolls, so some are always hidden.

F2
No max-width; label–control gap grows with the window.

The Row primitive puts a 180px label next to a full-flex control. At desktop widths the eye travels ~700px between a label and its value — the single biggest reason the page feels unfinished.

F3
Prose paragraphs break the row rhythm.

Explainers (billing notes, subagent notes, theme-seeding notes) render as full-width paragraphs between rows, so the form reads as interleaved article + form. The explanation belongs to the row it explains.

F4
The save model is ambient and mixed.

A permanent footer shows Save even when nothing changed; six sections (Appearance, Accounts, Network, Machines, Security, Updates) self-persist and ignore that button entirely. "Reset to defaults" sits one casual click away in the same bar, unguarded.

F5
Sparse tabs read as broken.

Appearance shows three unaligned fields in a huge void; Integrations and Background LLM are similar. Density is Podium's brand — emptiness here reads as neglect, not calm.

F6
Off-system styling.

13px generic rows, no mono labels, no engraved tiers, no hairline seams. It's the one surface that looks like a website settings page inside an instrument.

Direction

Register: product / Restrained (per PRODUCT.md — no override earned here). Anchor: Linear's settings — grouped rail, centered column, per-row definition. Three moves:

Carve the navThe section rail becomes a recessed Rail-Navy column with mono uppercase group labels — the same grammar as WORK/TRAY in the shell. Four groups replace the flat list; a filter field sits on top.
One measured columnContent lives in a 620px column. Each row is a two-cell grid: label + its own 11px description on the left, a 240px control on the right. Hairline seams between rows, section breaks as carved dividers. All existing prose collapses into row descriptions.
Honest savingThe permanent footer dies. Blob-backed sections get a floating "unsaved changes" bar that appears only when dirty (Save / Discard); self-persisting sections show nothing — they already apply instantly. Reset to defaults moves into a guarded spot.

The new information architecture

Seventeen flat tabs become four named groups. Every existing route (/settings/:tab) keeps working — this is regrouping, not renaming.

Key states & secondary surfaces

Connect flows become steppers

The Telegram connect flow is the most stateful thing in settings — today it's a numbered prose block plus a button. It becomes a proper sequence with live state (this is a real ordered process, so the numbers carry information):

Connect Telegram

  1. Bot token saved — @podium_ops_bot
  2. Open the link and send the prefilled start message  podium-8F3K
  3. Podium fills the chat ID and confirms here

Steps complete themselves as the poll advances; the countdown is a tabular-nums mono timer — the agent-state grammar reused. Failure states replace step 2 with the error and a retry, never a toast.

Mobile: index → section

Today the 17 tabs render as a horizontally scrolling chip strip. On phones, settings becomes two levels: the grouped index is the first screen, a section is the second, back returns. Same components, same routes.

The rest of the state matrix

LoadingSkeleton rows in the content column (label + control ghosts), never a "Loading settings…" string. The nav renders immediately.
SavedThe dirty bar's Save resolves in place — button flashes "Saved ✓" for 1.2s, then the bar slides away. No detached "Saved." text.
Save errorThe bar stays, turns its message into the error (Alert Red text), keeps Save enabled for retry. Errors live where the action was.
Leaving dirtySwitching sections with unsaved changes keeps the bar (the blob is one document — this is honest today and stays). Closing settings while dirty asks once.
Reset to defaultsMoves to the bottom of INSTANCE › Experimental as an explicit destructive-styled action with a confirm step. It leaves the ambient footer forever.
Sparse sectionsAppearance gains a live theme preview row (mini terminal swatch per theme); single-toggle sections merge into their group neighbors' rhythm rather than floating alone.
Search/ focuses the filter; typing filters nav items by section and row labels, jumping to the first match. Phase 3 makes it cross-section (flatten row index).
Keyboard↑/↓ move sections when the nav has focus, Esc closes settings (unchanged), the dirty bar's Save binds ⌘S while settings is open.

What doesn't change

The load-whole-blob / save-whole-blob architecture, the SECTION_VIEWS lookup, deep-linkable /settings/:tab routes, the Telegram poll living in the view, and all section business logic. This is a shell-and-primitives redesign: SettingsView.tsx (nav, header, save bar) and shared.tsx (Section/Row grow a description prop and the grid layout), then a mechanical sweep moving each section's prose into row descriptions.

Build plan

PHASE 1
Shell + primitives.

Grouped engraved nav with filter field, 620px content column, new Row grid with descriptions, dirty-tracking save bar (blob sections only), Reset relocation, skeleton loading. All 17 sections render correctly in the new shell with their existing markup.

PHASE 2
Section sweep.

Move every inline explainer into row descriptions; rebuild the Telegram connect flow as the stepper; Appearance theme-preview row; mobile index→section navigation.

PHASE 3
Depth.

Cross-section row search, Accounts + API keys merge ("Accounts & keys"), ⌘S save binding, per-row deep links (/settings/sessions#auto-continue).

Open questions

Q1Merge Accounts + API keys now (Phase 1 IA change, copy already treats them as one) or defer to Phase 3? I'd defer — the merge touches credential flows worth their own review.

Q2Auto-save instead of the dirty bar? Linear auto-saves everything. The whole-blob save makes true per-field autosave risky today (partial intents overwrite each other across devices); the dirty bar is the honest step, autosave a candidate after per-field mutations exist server-side.
