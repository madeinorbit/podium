Four cuts. No data lost.

Every fact in the left column is still in the right one — it just stopped competing.

01

Yellow means exactly one thing

It marked review pills, merge pills, uncommitted counts and badges — so it marked nothing. Now yellow is reserved for "you're needed". Uncommitted and commit refs drop to dim mono. Suddenly the three rows that actually want you pop.

02

Unread is a dot, not a banner

NEW MESSAGE appeared nine times — it became wallpaper. A blue dot on the agent avatar says the same thing in a tenth of the space, and the eye can skip the rows that don't have one.

03

One status line, one voice

A status icon, a boxed pill, a timer and an "ago" stamp said the state four ways. They fold into a single mono line — needs review · 12h — the ask tinted, everything else dim. The redundant ⓘ / ✓ icon is gone.

04

A right gutter that holds still

Chips, avatars and refs floated at every x and y. Now the right edge is one fixed column: the single attention token on top, quiet git facts beneath — revealed on hover. Bigger rows, so POD-187 finally reads.

Agents are a count. Subtasks are rows.

POD-281 drew the right line — agents and sub-issues are different things and shouldn't share a box. This keeps that line and pushes one step further: the sidebar is for triage, so the agent detail moves to where you act on it.

In the list, agents are a number

The row already says 3 agents · working. That count is the signal: a fan-out is running here. No agent gets its own row by default — that's the density we just removed. If one needs you, its yellow bubbles up to the row's single token; you don't have to expand to know.

›

Two rails, one meaning each

Expand and the distinction is visible, not implied: a neutral rail of one-line workers (who + state, nothing else), and an issue-tinted rail of subtasks — real sub-issues with their own IDs you can select. Only subtasks are ever full rows.

›

Inside the task, workers are tabs you can't close

The confusion was closable agent tabs — closing a live worker means nothing. Make them non-closable while live; they retire themselves when they finish (as delegate sessions already decay). The agent area becomes an honest live roster; the sidebar just counts it.

Closed & suspended, on one line.

Below the live work sits the archive. The moment an issue stops needing you, it stops taking up room — half the row height, none of the noise, the archive still one click away.

One line, because there's nothing to do

An item that's done or parked is out of triage. So the row drops to ID · title · how it ended — merged, superseded, snoozed 3h. No avatars, no timers, no status pills, no counts. Roughly half the height, so 45 closed issues scan in a glance.

›

Archive stays one click away

Hover any row for a per-item archive; each fold header carries archive all to clear the group. The shortcut you liked, kept — just quieter until you reach for it.

No unread down here. A closed or suspended issue has nothing to announce — the concept forbids the new message badge on these rows outright. Today POD-271 still shows one; that's a real state bug (unread not clearing on close/suspend), and an agent is tracing exactly where the guard is missing so it gets a fix, not just a paint-over.
