Spine line variants

POD-516 · round 3
The problem

The tree lines work, and they are boring.

Column 2 is a live tree: issues nest into issues, sessions hang off issues, native subagents hang off sessions. It renders flat: one strip per row, each row drawing the rail segments that cross it plus its own elbow, so a filter or a search can drop any row without re-parenting anything. Every variant below keeps that, and every variant below uses the exact geometry constants in FlightDeck.tsx:84-99.

Today every line is one 1px bg-hairline-soft span. It states topology and nothing else. On a surface an operator watches all day while a dozen agents work, the lines are the only element that touches every row, which makes them the cheapest place in the product to put state and life, and the most expensive place to put decoration.

Same tree, three times. Three levels of issue nesting, a branch with several sessions, one session with its own native subagents, one blocked task, one done task, one proposed task with nobody on it, and one session that stopped and needs you. Drag COL to the narrowest column the shell allows; toggle Daylight and reduced motion.

01

The Current

motion · event-driven hold
Mission spine7 tasks · 4 running
a session just stopped and asked

The idea. At rest the spine is exactly what ships today: a 1px hairline that says topology and nothing more. All of the expression is spent on events. When something real happens, a single pulse of light runs the actual ancestry path from the trunk down to the row it happened on, arrives, and dies. The deck stops being a picture of the mission and becomes an instrument reacting to the machines: you catch movement in your periphery and your eye is already travelling to the row before you have read a word.

The travelling band is a 26px gradient inside the 1px rail, translated on the GPU, with a per-segment --d delay so light appears to run continuously across rows that are drawn independently. The elbow it lands on flashes once and decays back.

Where it breaks. Two places, and both are structural. First, at eight concurrent agents the events never stop, and a stream of one-shots is indistinguishable from perpetual motion, which the Agent State Grammar reserves for the braille spinner alone, precisely so "something is computing" has exactly one voice. Second, motion is the product's scarcest signal and this spends it on every transition, including the ones the operator does not care about. It would need a coalescing rule (one pulse per branch per second, and only for events an operator would act on) before it is safe. A rule that has to suppress most of its own output is a sign the idea is too loud for the job. Resting state also stays exactly as boring as today's, which is the actual complaint.

Per row
Identical to today at rest: one 1px span per rail. Zero animated nodes when nothing is happening.
Per event
One ::after + one transform animation on each segment of the path, ~340ms, then removed. Path length ≈ tree depth, not row count.
Reduced motion
No travel; the path holds its lit tone for ~1.2s and returns. Legible, still.
02

The Milled Channel

material · carved build this
Mission spine7 tasks · 4 running
260ms, one shot, then still

The idea. The tree is not drawn on the column; it is cut into it. Every rail is a 2px channel with two lips, a shadow lip and a lit lip, which is the Wells bevel from DESIGN.md §5 stood on end, lit by the same upper-left light as every other groove in the product. The elbow stops being an ASCII corner and becomes a milled bend with a real 6px radius. Nothing floats, nothing glows: the spine gains depth by going further in, which is the one elevation move this system actually owns.

Three things ride on that material for free. Depth is the channel getting shallower (level 1 full, level 2 at 74%, level 3 at 54%), so nesting reads even where the indent is only 14px. Identity is the issue colour mixed into one lip, at hairline strength: a trunk carries the colour of the branch it is and an elbow the colour of the child it turns into, so a violet mission sprouts a cyan sub-branch and you can see which is which without a single saturated line. State is a property of the metal rather than a colour: a done branch's elbow is welded flush to one line, a blocked one is broken into a 3-on/3-off stipple by a mask, a retired one keeps its indent and gives up its groove. None of it touches the pass-through trunk, which belongs to the parent. Only one thing is allowed to take a hue: the segment from the junction down to a session that stopped and asked, which is the literal definition of the Signal Rule.

Where it breaks. Which lip carries the meaning has to flip between the themes, because on navy a recess catches ambient light and on paper it casts shadow. So this is two tokens and one mapping rule rather than one colour, and a call site that hard-codes a side will look right in exactly one theme. Beyond that: the two lips are 1px each, so on a fractional device-pixel ratio they blur into one soft 2px line and lose the bevel. It degrades to a slightly heavier hairline, never to mud, and the geometry constants already keep every rail on an integer pixel. It also has no life of its own, which is why it takes exactly one motion event: the join gesture, the channel reaching down and out to meet a session that just arrived.

Per row
Same node count as today (one span per rail, one per elbow), plus one ::before on each elbow. No extra DOM, no JS, no animation at rest.
Paint
Two-stop linear-gradient instead of a flat colour; the blocked stipple is a mask on an element that is already composited. Free at 40 rows and free at 400.
Reduced motion
Nothing to disable except the join gesture. The resting tree is already still.
03

The Load-Bearing Spine

information · weight hold
Mission spine7 tasks · 4 running
the node ignites, the elbow draws out

The idea. Make the line carry information it is currently wasting. A rail segment is drawn in proportion to how much live work hangs off it downstream: the trunk is heaviest near the root where all the work converges and thins toward the leaves, so a glance at the left edge tells you where the mass of the mission is before you read a single title. Every junction becomes a 4px node: hollow when nothing lives below it, filled when something does, in the child's own issue colour when it has one, flattened to a bar when the branch is done, barred through when it is blocked, gone when it is retired. It is the most useful of the three: it answers "where is the work" with geometry.

Where it breaks. Three ways. It needs a real derivation, downstream live-session load per segment, which is a new backward pass in mission.ts and a new number to keep correct on every store update. Weight is already spoken for: this system uses line weight for depth, and a line whose weight also means load gives one channel two meanings, so a deep quiet branch and a shallow busy one become hard to tell apart. And the nodes are the christmas-tree risk: at 40 rows you get 40 small marks down the left edge, each individually justified, collectively a beaded curtain. Nodes are also the one element here that competes with the stage glyph 8px to their right for the same "what state is this" question.

Per row
One extra 4px node per junction (~1 per row), plus a --load custom property per rail. Widths change via clip-path, never layout, so no reflow.
Derivation
New: O(n) backward pass beside treeGuides, recomputed whenever sessions change. Today's guides need no such thing.
Reduced motion
Only the join ignite is motion; everything else is static.
The recommendation

Build 02, The Milled Channel — plus exactly one gesture from 01.

The complaint is not that the spine lacks features; it is that it is boring, and the resting state is 90% of the time. 01 leaves the resting state exactly as it is and buys life with motion this product has already decided it will not sell. The braille spinner is the one perpetual voice, on purpose, and a stream of pulses from eight agents becomes a second one. 03 is the cleverest of the three and the only one that adds information, but it pays for that with a new derivation, a second meaning on a channel that already carries depth, and a bead down every row.

02 is the one that makes the surface look more like itself. It takes the system's own signature (carved, not floating; separation earned with ground, inset edges and hairlines) and applies it to the one element that touches every row. It costs no new DOM, no JS, no derivation and no perpetual motion; it makes depth, branch identity and blocked/done/retired state all legible at 8px of horizontal space; and it obeys the Signal Rule strictly, spending a hue on exactly one thing: the segment pointing at the session that stopped and asked you a question.

What to build, in order
  1. Give Hung and BranchGuides a channel instead of a bg-* class. The rail span becomes 2px carrying two 1px background layers, one per lip, each a vertical gradient with a stop at --hot. The elbow becomes a bordered box with border-bottom-left-radius plus one ::before inset 0 0 1px 1px for the second lip. Node count per row is unchanged from today.
  2. Model the lips as roles, not sides: --meaning (the lip that carries colour and state) and --bevel (the lip that only makes it a groove). One mapping rule puts meaning on the left lip in Daylight and on the right lip in dark, because a recess on navy catches light and a groove on paper casts shadow. It is the same inversion the Wells already make (index.css:503-516). Every rule after this one is theme-agnostic and only ever sets --meaning. Two new tokens: --groove-meaning (+ a -quiet sibling) and --groove-bevel.
  3. Pass depth down as --shallow (1 / 0.74 / 0.54) and state as a data attribute. done sets --bevel: transparent, which collapses the channel to one welded line; blocked applies the 3px/3px repeating mask (180deg on rails, 90deg on elbows); retired drops the bevel and falls to 0.3.
  4. Two rules keep it honest about ownership, and they are the ones easiest to get wrong: a pass-through trunk carries the parent branch's colour and never the crossing row's state (it belongs to the parent and has to stay continuous), and the elbow carries the child's colour and the child's state. Mix through the existing --issue-line-scale so light and dark scale themselves.
  5. Keep exactly one hue rule: the hung rail serving a session with sessionNeedsHuman sets --meaning-hot: var(--attention) and --hot: 13px, so the tone runs only from the top of that segment to its elbow and stops. No ancestor rail is ever tinted by a descendant's obligation; the strip already carries the dot.
  6. Add the join gesture last: the new elbow reveals with clip-path: inset(0 100% 0 0) → inset(0) over 260ms and its rail scaleY(0→1) over 200ms, one shot, gated the same way usePhaseMorph already gates the phase morphs so a freshly mounted list never replays them.
