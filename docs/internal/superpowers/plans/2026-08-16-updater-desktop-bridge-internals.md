# Desktop updater bridge internals (Rust side) — Implementation Plan

**Epic:** POD-2087 · **Spec:** `2026-08-14-update-operations-design.md` §5, §9.4
**Protocol:** `2026-08-14-updater-worker-protocol.md`
**Blocked by:** nothing. This is the half of the desktop work that does not depend on the
operation contract or the panel, carved out so it can proceed in parallel.

**Goal:** The Tauri shell stops being a black box during an update: it reports install
progress, returns typed errors instead of bare strings, resolves its channel from one
authority, and can update itself when the page is broken. No web behavior changes — the
page-side wiring is POD-2104, which consumes what this issue exposes.

**Owns (exclusively):** `apps/desktop/src-tauri/src/updater.rs`,
`apps/desktop/src-tauri/src/main.rs`, `apps/desktop/src-tauri/permissions/**`,
`apps/desktop/scripts/verify-update.sh` and `serve-update-feed.ts` if the drill needs
them. **Do not touch `apps/web/**`** — POD-2102 (panel) and POD-2104 own that; a change
there will collide. Adding a type-only declaration to `apps/web/src/lib/nativeDesktop.ts`
is the single permitted exception and only if it is additive and optional.

## Context (verified at `cf9ec8c2b`)

- `install_update` (`updater.rs:167-200`) discards both `download_and_install` callbacks
  (`|_chunk,_total| {}, || {}`), so the page can only show a static spinner.
- Errors are bare strings and every early return is untyped; the page cannot tell
  "debug build refuses" from "download failed".
- Channel disagreement: `check_update(channel)` takes the page-supplied (server-resolved)
  channel, `install_update` re-checks with the shell's own `~/.podium/config.json`
  (`updater.rs:185`) — two authorities for one decision.
- Native fallback is inert: `check_and_prompt_update` (`updater.rs:206-214`) returns
  immediately unless `PODIUM_UPDATE_AUTOCONFIRM=1`, so a shell whose webview fails to load
  has **no** update path, despite the ownership-grace machinery working
  (`OWNERSHIP_GRACE_MS = 8s`, `should_show_native_dialog` at `:84-86`).
- `tauri_plugin_dialog` is already registered (`main.rs:375`); there are currently **no**
  Tauri events anywhere (`grep '\.emit('` in `src-tauri/src` is empty).
- Bridge discipline: `window.__PODIUM_DESKTOP__` is frozen and injected as an init script
  (`main.rs:260-301`); both sides feature-detect. Keep that — an older page must tolerate
  a newer shell and vice versa.
- No local cargo: every decision must be a pure function with `#[cfg(test)]` coverage;
  full builds verify in CI.

## Tasks

- [ ] **Progress events.** Thread the real callbacks of `download_and_install` into a
  window event `podium://update-progress` carrying
  `{ phase: "downloading" | "installing", received: u64, total: Option<u64>, percent: Option<u8> }`.
  Gate emission with a pure `should_emit_progress(last_emitted_at, last_percent, now, percent)`
  — every 2 s **or** every 5 percentage points, whichever comes first — mirroring the
  daemon-side rule in POD-2101 so the two surfaces feel identical. Unit-test the rule
  (including unknown total → bytes only, no percent).
- [ ] **Typed errors.** Introduce `UpdateErrorCode`
  (`debug-build | no-pending-update | download-failed | signature-invalid | install-failed |
  restart-failed | no-update-available`) and return `{ code, message }` from both
  `check_update` and `install_update`. Every early return gets a code; `message` stays
  human-readable and never carries a path or a token. Serialize as a stable JSON shape —
  it is contract for the page, so treat it under the frozen-contract law (additive only).
- [ ] **One channel authority.** `install_update(channel)` takes the channel as an
  argument, from the same source `check_update` uses (the page, which asked the server).
  The shell-config lookup survives **only** on the native-fallback path, where there is no
  page. Pure-test the precedence: argument wins; config used only when no argument.
- [ ] **A real native fallback.** When the page has not claimed ownership within the grace
  window, present an actual dialog (the already-registered `tauri_plugin_dialog`):
  "Podium {version} is available — install and restart?" → on confirm, install with
  progress reflected in the window title, then restart. Delete the interactive
  `PODIUM_UPDATE_AUTOCONFIRM` bypass and replace it with an explicitly test-only override
  (rename so its purpose is unmistakable, e.g. `PODIUM_UPDATE_TEST_AUTOCONFIRM`) that
  `verify-update.sh` sets. Extend the existing `should_show_native_dialog` tests to cover
  the confirm/decline outcomes.
- [ ] **Capabilities.** If the new event needs a permission, extend the existing
  `update-bridge` capability (`main.rs:644-662`) and the autogenerated permission files —
  including the remote-origin and post-transfer regrant paths, which already exist and
  must keep working.
- [ ] **Do not** change `apps/web` behavior, the operation contract, or anything under
  `apps/server`.

## Testing

Rust `#[cfg(test)]` for: the progress-emission rule, every error-code mapping, channel
precedence, and the fallback decision incl. dialog outcomes. Prove each new assertion can
fire (break the code in place, watch it go red, restore) and say so in your issue state.
There is no local cargo — if `cargo test` is unavailable, say so explicitly rather than
implying you ran it, and note that CI is the proof.

Then the Linux drill: `bash apps/desktop/scripts/verify-update.sh` (with
`serve-update-feed.ts`) — both arms: a good signed artifact installs and relaunches at the
target; a broken artifact fails closed and leaves the old build launchable. macOS
production-signed verification is release-time only (`docs/agents/updater-acceptance.md`
§5) — record it as an open verification item, never claim it.

Repo gates per the protocol: shared lanes are red at the base (POD-2109), so land on
owned-scope green plus the byte-identical comparison; disk is tight (POD-2111), so check
`df -h` before builds and never create a second worktree.

## Acceptance

- A desktop install emits progress events at a bounded rate, and every failure path
  returns a typed code.
- `install_update` cannot disagree with `check_update` about the channel.
- A shell whose page never claims ownership presents a real dialog within ~9 s and can
  install and restart from it.
- `apps/web` is untouched (`git diff --stat` proves it).
