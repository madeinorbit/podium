POD-227 · UX review

The sidebar has good data, but too many competing status signals.

The two rows are technically accurate. They are not yet instantly readable. “Done” and “working” should be the first distinction the eye sees; today the user has to interpret several tiny, position-dependent marks first.

B−
Useful for an expert, not best in class yet.

There is a thoughtful model underneath, especially the human-attention precedence and live timer. The presentation over-exposes that model: lifecycle, unread state, agent presence, git state, push state, and time all compete inside one 92px row.

Issue identity tile

POD 212 is the human-referenceable issue ID. Its solid border means live/recent work; queued/idle uses a dashed, dimmer treatment. A click also opens issue color selection.

2

Unread update

The standalone blue dot says the row has changed since you last opened it. It is hidden while the row is selected.

3

Agent presence

The orange Codex/OpenAI tile says one Codex agent belongs to the issue. With more agents, up to two tiles stack, then a +N overflow appears.

4

Aggregate agent-state dot

The tiny corner dot belongs to the agent tile: blue is working, yellow is waiting on the human, gray is everything else—including done and queued. It is not the unread dot.

5

Issue lifecycle summary

done / working summarizes all sessions. Waiting on the human takes precedence over working; all sessions must be finished before it reads done.

6

Git-state dot

A solid blue dot means committed/clean; half amber means dirty; a dashed gray ring means no commits or no changes. This is unrelated to both other blue dots.

7

↑1 means the private issue branch is one commit ahead of its parent branch.

∑ 56:55 is the cumulative agent working time after completion. The sigma means “sum,” not a warning or process state.

The half-filled amber dot on the working row indicates uncommitted changes attributed to that issue/worktree.

10

Not pushed

The amber ⇡ means some commits are not on the upstream remote yet.

11

Live work timer

The animated braille glyph is the “working now” signal; 51:05 counts active compute time from the earliest working agent, including its accumulated base.

Why “done” versus “working” is not clear enough

3 blue dots

Color has no stable meaning

Blue means unread, actively working, or clean git. The user must first locate the dot, then remember the local grammar. Color should accelerate recognition, not require positional decoding.

4 status channels

The same state is repeated

“Working” appears as text, a fleet corner dot, an animated braille glyph, and a counting timer. “Done” appears as text, a gray fleet dot, stillness, and sigma time. The repetition adds noise without adding certainty.

Wrong first glance

The finished row can look more active

The done row has two bright blue dots and an upward arrow. The working row has one tiny blue corner dot. In peripheral vision, the completed row can therefore attract more attention than live work.

Answer to the screenshot question: no—the difference is decipherable, but not pleasantly or immediately clear. The words do the real work; the surrounding marks partly contradict their hierarchy.

A simpler row grammar

Keep the valuable information, but give each line one job: identity on line one; lifecycle and time on line two. Show source-control metadata only when it changes the user’s next action.

One lifecycle signal

Put icon, word, color, and time into one left-aligned lockup. Remove the fleet corner dot; it duplicates the same aggregate state.

Identity stays identity

Keep the Codex tile to answer “who is on it?”—without making the tile also carry lifecycle. Only stack/count it when multiple agents exist.

Exceptions, not telemetry

Hide the clean git dot and sigma. Surface plain-language git metadata only when dirty, unpushed, ahead, conflicted, or ready to merge.

Recommended priority

1 · Remove the fleet corner dot

Lowest-risk, highest-noise reduction. The row already has a canonical aggregate status and the live spinner.

2 · Stop showing clean as a blue dot

Silence is a better representation of “nothing to act on.” Preserve details in the Git panel and hover title.

3 · Replace symbols with short copy

∑ 56:55 → 56m total; ⇡ → Unpushed. Tiny symbols can remain in expert tooltips, not as the only explanation.

North-star rule: a user glancing for half a second should see exactly one of three things first—Needs you, Working, or Done. Agent identity, unread state, git, and time should never outrank that answer.
