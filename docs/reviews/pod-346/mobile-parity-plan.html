00 · the one that matters mostNothing you fix reaches the phone

Root cause

Your phone had never run the code we merged. apps/mobile/dist — the bundle the backend serves at /mobile — was last built at 00:30. The superagent chat fix (POD-344) landed on main at 00:35. Five minutes late, so the phone kept running the broken screen.

The repo ships the units that exist to prevent exactly this — podium-web.service (“rebuilds apps/web/dist and apps/mobile/dist … runs at boot and on every redeploy”) plus podium-redeploy.path. Neither is installed on this machine. Only podium-server, podium-daemon and podium-janitor are. So both bundles change only when a human remembers to run the build.

That single gap is the whole premise of this issue: “a lot of recent changes did not yet make it to mobile.” They were written. They were merged. They were never built.

Now: merged and both bundles rebuilt by hand, verified against the running server. Still open: POD-347 installs the units so the next merge doesn’t go stale the same way.

01The two bugs

Superagent send — “just nothing happens”

Not a send bug. The turn dispatched fine; the screen could not show it. The phone built its transcript from superagent.history — the frozen legacy buffer, which on your live database has zero rows. So the bubble sat on “sending…” forever and the reply never appeared. POD-344 had already rewritten it to read the thread’s headless session transcript. The code was fixed; only the deploy was missing.

Added on top, so “nothing happens” is structurally impossible: a rejected send now marks its own bubble not sent, prints the server’s reason, and offers Try again with the words intact.

“I added a task in the Work tab and nothing ever happened”

The Work tab’s + opened New session, not New task. A session made that way is bound to no issue and no worktree — and the Work list is derived from issues and worktrees, so the agent it spawned was invisible by construction. It was not lost: one was still running in the shared root checkout, on main.

Now + opens a sheet whose first, primary action is New task, with New session one step down and each option saying where its work lands. A task with nobody on it also gained a Start an agent button.

03What “best in class” actually needs

Parity alone won’t make this feel like a great phone app. These aren’t on the desktop at all, and they matter more than most of the table above.

  1. Push notifications. The whole value of Podium on a phone is “an agent needs you and you’re not at your desk.” Today there is no notification path — the server’s notify module only speaks Telegram. Nothing tells you an agent asked a question. This is number one.
  2. Make the phone app installable. The desktop web app is a real PWA. The Expo web export ships no manifest and no service worker — so the surface that lives on a home screen is the less installable of the two. Push depends on this.
  3. Deep links from a notification into the exact card that needs a decision.
  4. Voice input. Dictating a task while walking is the phone’s comparative advantage.
  5. Swipe actions. Snooze / tuck / archive each cost a long-press plus a sheet today.
  6. Pull-to-refresh — the only manual resync when the socket is wedged, which is exactly when you want one.
  7. Android keyboard avoidance — currently iOS-only.
  8. A visible connection state. When the socket is down the phone silently shows stale data.
