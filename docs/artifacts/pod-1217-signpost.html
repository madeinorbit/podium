Why it says that

There is a live-session check further down the same function, and it is tempting to call the bug a misplaced line. It isn't. That check was written for a different case — an agent hopping to a spin-off — and its own comment says so. The duplicate branch simply returns before it, having never asked about sessions at all.

packages/client-core/src/viewmodels/mission.ts
const targetId = issue.supersededBy ?? issue.duplicateOf
if (targetId) return { … } ← POD-1217 leaves here, sessions unread
…
if (sessions.some(onThisTask)) return null ← a spin-off rule, not a general one

Note the ??. Superseded tasks ride the same branch, and a superseded task with a live agent is a genuinely different judgement — there, the work really did continue elsewhere. Any fix should say which of the two it is changing.

The fix

Fix the one sentence, at the card

recommended

Only the first sentence makes a claim about sessions. The headline is a lineage fact and stays true no matter who is here; so does the half about POD-1160. Give the card the task's sessions and let that one sentence read them — "Codex is parked on this task" when somebody is present, today's wording when nobody is.

Small on purpose: one component, one conditional. The shared viewmodel is not touched, so every other surface that leans on it keeps working.

rejected

Check for a present session before the duplicate branch, so the whole continuation returns nothing. This was the first draft's recommendation, and it costs far more than it looks:

And it never comes back. A parked session still counts as being on the task, and sessions here park rather than exit — so on POD-1217 the trail to POD-1160 would disappear for good.
