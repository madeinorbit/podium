# A2a push-observer design — 2026-08-30T04:26:00+02:00

## Boundary inspected

The daemon sends `agentState`; the server persists it on the session and pushes a per-session `sessionAgentStateChanged` frame without rebroadcasting `sessionsChanged` (`apps/server/src/relay.test.ts`, agent-state test). The protocol classifies `sessionAgentStateChanged` as `stream.live` (`packages/protocol/src/messages/message-class.ts`), while the browser durable replica consumes `feedBootstrap`/`feedDelta` separately (`apps/web/src/lib/kernelReplica.ts`). A2a must therefore observe the direct `/client` WebSocket state push, not serialize `sessions.list` or wait on the durable feed.

## Observer

1. Open and authenticate `/client` before the turn, attach/subscribe to the target session, and install the frame handler before sending. Record an initial authoritative idle snapshot.
2. For every matching `sessionAgentStateChanged`, synchronously record local monotonic receive time, wall-clock receive time, the full `state`, `state.phase`, `state.since`, and `state.stateObservedAt`. Preserve every transition in arrival order.
3. Call `sessions.sendText` with the short 1-to-12 nonce turn. Record call-start separately, then record monotonic and wall-clock acceptance immediately when the RPC returns.
4. Continue until the assistant nonce is observed and a pushed state has settled idle. Never insert an HTTP state query in the timing path.

## Deciding both sides of two seconds

A working push received within 2000 ms of send acceptance proves the transition was prompt by an upper bound. A later receive is not itself a failure because transport can delay it; FAIL requires the pushed authoritative `state.since` (or `stateObservedAt` when that is the source timestamp), on the same host clock, to be strictly later than acceptance wall time plus 2000 ms. If neither timestamp is present/valid, the prompt clause is PARTIAL rather than FAIL. Record both timestamp delta and receive delta so clock/source and delivery latency remain distinguishable.

Continuity is evaluated only over ordered pushed transitions: idle or blank strictly between first and last working is flicker. The final clause passes only on a pushed final idle after the assistant nonce. This observer resolves PASS and FAIL without inferring a transition inside a blocking HTTP round trip.
