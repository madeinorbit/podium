## 4. Findings for later phases

- F-clock (arm). On the history-faithful fixture corpus a boundary-free
  +60s tick re-runs 3,589 derivation bodies (3,499 flat + 86 summary + 4
  aggregate, pinned by `mobx.clock.test.tsx`) and commits 0 rows; the hand
  arm re-runs 259 on the same tick shape. Mechanism: every flat/summary
  whose row holds a finished member subscribes to the coarse clock through
  its retention check and stays subscribed forever — settled rows re-run per
  tick and settle by equality. The other half is also measured: a +60d jump
  (the smallest forward jump that moves oracle rows at wall-clock boot, 14
  rows) commits EXACTLY the 14 still-visible movers, zero over-commit, zero
  under-commit, parity green. So the subscription completeness has value
  (no stale clock rows, by construction), and the price is O(subscribed)
  settled bodies per tick (browser clock actionMs p50 41 ms vs rename 14 ms
  under shared load). The safety side matters for the decision order
  (SAFETY first): the hand arm's 259 comes from 3 hand-maintained
  sensitivity sets (H4: a place to remember) — a new clock-dependent rule
  that forgets its set goes stale silently, the exact foot-gun class the
  K-phase prices. A clock quantum (read a coarsened bucket instead of raw
  ms) would cut the per-tick cost inside the idiom; it is J-phase slope work
  with parity risk, explicitly deferred — the M2 budget letter is met (0
  commits; settled re-runs only).
- F-origin (arm, minor). Renaming an origin row re-derives one dependent
  tick (rowsDerived 2, row commits 1 + tick ride): visible only where dep
  edges are live, i.e. the fixture/browser path — see F-seed.
- F-seed (harness, G3 — for the coordinator). The scenario seed writes dep
  edges as entity `issueDep` (`scenarios.ts`), but the row source listens on
  the `issueDeps` address (`row-source.ts`); the seed's R4 edges look inert
  on the scenario path (count-harness rename is rowsDerived 1 invariantly,
  never 2). R4 is covered on the fixture path (browser rename 2-shape,
  `mobx.fixture.test.ts`) and the unit path (`mobx.test.ts` origin-tick
  test), so no verdict changes — but the K-phase exercise E aims at removal
  paths, and it should know which corpus actually carries edges.
- F1. Genuine lane/target moves still pay O(unbound × roots) per re-resolve
  (~615 × ~1,000 at 1x); a prefix trie removes it. J-phase with M3
  lifecycle scenarios, which are the first inputs that move lanes.
- F2. `moveSeat` is O(repo buckets) per issue ingest on EVERY issue write
  (500 visits at 1x, counted but unwritten — `indexUpdates` stays 0). The
  targeted-seat fix is J-phase; until then repos-per-write is the slope to
  watch at 2x/4x.
- F3 (harness, G4 — confirms hand-M2 F3). Browser commit logging never
  worked on any arm; needs a G4 follow-up before J-phase walls.
