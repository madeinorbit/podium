Judgments: `move-seat-scan` (O(repo buckets) = 500 at 1x per issue ingest;
two `moveSeat` calls per ingest, one per seat map) REMOVABLE via targeted
seat tracking (remember each issue's current bucket, drop directly instead
of scanning all 500) — the biggest per-event slope item, J-phase.
`roots-spread` (O(lanes + targets) ≈ 1,000 at 1x per `resolveCwd`) and
`resolve-unbound` (O(session homes) per genuine re-resolve) are 0 on every
M2 path after the fix; short of a prefix trie they are INHERENT, priced for
lifecycle (J-phase M3, scenarios 11–13). `visible-enumeration` (O(issues)
per invalidation touching the map or any visible) INHERENT — it is the ONE
allowed enumeration (§5.3/H4); per-row reads are cached, so the cost is the
walk, not derivation. `order-sort` / `groups-bucket` (~V per
order-affecting change) INHERENT to sequence rebuild (same judgment as the
hand arm's `groups-rebuild`). Removed waste: the stale-flag full re-resolve
(4,304 home visits + 614k root spreads on the first post-mount event, zero
seat changes).
