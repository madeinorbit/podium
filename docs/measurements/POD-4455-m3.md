## 7. Write-path sketch

`docs/plans/POD-4455-write-path.md` (one page) + `arms/tanstack/spike/`
(one optimistic title rename through `createOptimisticAction` + direct
collection updates as transaction-local state: pending commits 1 row with

levels, dead-letter needs one row-visible field plus a render read (no new

## 8. Arm delta, size, and the rescope finding

`queries.ts` (fn walls, +40), `rollup.ts` (entry walls + sync-write
last-writer-wins dedup), `store.ts` (+~110: `phaseMs`, `buildGraph` /
`teardownGraph`, rebuild-on-replace): 4,127 non-test lines (+208 over
M2), spike/ excluded from the count and never imported by the production
path. No shared/ change, no harness change.

No compression was attempted: the M1 breakdown stands (below ~2,700 means
dropping parity-exact rules or merging queries the criteria require
separate), and M3 added instrumentation plus a correctness fix. Still the
largest arm, still over the line budget — openly, with the weight named
in §6.

The rescope finding (the milestone's oneBehavior change): pushing a bulk
reseed through the live graph throws `Query contributors with the same row
key are not congruent` out of the 0.9.2 join canonicalization (bisected:
issues-only and sessions-only reseeds throw at volume; worktrees-only
passes; chunked and kind-ordered reseeds still throw — it is not volume
per transaction or kind order, it is transient same-key contributors
mid-drain). `replace` now tears the graph down and rebuilds it over the
new corpus — the proven bootstrap path, green at 1x/2x/4x mounts — while
the retained commit layer transitions rows incrementally (only moved rows
re-commit). One replace event in, full-once install out; lifecycle §1 is
the pin. Bonus: the same change fixed disposal ordering (dependents
first — the old list cleaned `issuesN` while `verdictR` depended on it),
so principal-switch teardown is now error-silent.

## 9. Query-count classification (coordinator item: inherent vs artifact)

Both, separated with evidence:

- ARTIFACT of the counting unit. Each touched row evaluates twice per fn
  stage (retraction + assertion), and this arm counts fn evaluations where
  MobX counts settled bodies and hand counts delta handlers. #2 reads as
  1 committed + 1 rowsDerived + 7 rollupsDerived + (2 narrow / 2 resolve /
  2 verdict / 2 summary / 2 lane / 4 rows) against MobX's 1 + 1+3. Same
  0/1/0 rows committed as both finished arms on #1/#2/#3. The decision
  document should compare rows-committed (flat everywhere, §2), not fn
  runs.
- INHERENT to eager IVM. Keyspace changes and locals writes re-run fns
  broadly with value-equal suppression containing commits: the Q-T5 anchor
  archive re-runs 7,826 resolve + 7,832 verdict + 9,247 summary + 9,736
  lane with zero over-commits (§10). The absolute run count scales with N
  on THOSE paths (runs ∝ N, commits flat) — the approach's constant-factor
  eagerness, priced in the M2 F-keyspace item, not a per-event slope.
- Scale evidence (M3): per-scenario run counts are identical at 1x/2x/4x
  on value-change events; per-evaluation fn walls are microseconds at
  every scale (`fnMs` table in the JSON). Nothing on the event path
  enumerates or allocates with N except the two named cached walks (§2),
  which commit nothing.

## 10. Q-T5 fan-out (runnable at last)

M2 could not run it (corpus had no shared worktrees — `verdictR` 0). The
R3-anchor corpus carries 559 `verdictR` rows over 465 anchors (max 2
sessions per anchor) at the 1x mount. Archiving the top anchor (i101, 2
R3-resolved sessions): the R3 join re-evaluates (`verdictR` fn walls
1.4 ms of the step — the shared `verdict` run counter cannot separate
verdictQ from verdictR, but the ms split can) while every output settles
value-equal (zero `verdictR` change events), commits stay contained
(0 commits ⊆ 1 oracle-changed row — the archived row unmounts uncounted),
parity green. Fan-out proved both halves: it ran, and it settled.
