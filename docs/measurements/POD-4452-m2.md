## 4. Findings for later phases

- F-visible (arm — THE M2 miss, fixed). Archiving a visible row left it
  committed: `visibleQ`'s pure-DSL `where` retraction emits no change
  event when an upstream update makes a row fail the predicate (state
  goes correct, subscribers hear nothing — verified by direct
  subscription tap: `visible-changes=[]` while `visibleQ.get('i4')`
  went present→undefined). The rollup's `flat` set kept i4, `final`
  stayed true, the row stayed committed. Fix: flat membership is
  mirrored from `summaryQ` events (the `fn` query notifies on every
  (excluded, flat) flip — a visible change requires a summary value
  change by construction, so the mirror is complete); the `visibleQ`
  subscription is removed, the collection stays as the graph's declared
  visible set and the bootstrap seed. Before: #6b parity FAIL (extra
  [i4]); after: green, all other counts identical.
- F-framing (library). Sync `update` ops surface to `subscribeChanges`
  as `insert` (reproduced minimally: one seeded row, one update, one
  observed `insert`). Harmless everywhere in this arm — no handler
  branches insert-vs-update — but the M1 "updates propagate as
  retraction+assertion pairs" note described live-query collections;
  entity collections reframe to insert. Handlers must keep driving by
  key, never by type (delete excepted: genuine removals).
- F-keyspace (library, priced). Inserts, deletes, and locals writes
  re-run the graph's fns broadly (~7.8k resolve + ~6.7k verdict + ~9.2k
  summary + ~9.7k lane at 1x) with value-equal suppression containing
  commits to the budget. The re-evaluation breadth is engine-internal
  (not arm code) — a per-fn memo would be a cache keyed on input shape,
  i.e. precisely the scenario-keyed fix class M2 forbids. The slope
  price is `prefix-probe` (1.1M visits per keyspace change/tick at 1x:
  ~500 lane roots × ~2,200 unbound re-evaluations × ~2 waves).
- F-seed (harness, G3 — confirms MobX-M2 F-seed on this arm). The
  scenario corpus carries no R3 fan-out (`verdictR` 0 rows at 1x mount;
  issues lack `worktreePath`, no worktree entities), no dep edges
  (`dependentsOf` empty → `dependents-scan` 0), and no origin ticks —
  so the Q-T5 growth-corpus fan-out check cannot run on this corpus. R3
  is covered on the fixture path (`tanstack.fixture.test.ts` parity
  green at 211 visible rows, the corpus that caught the single-owner R3
  drop in M1). The K-phase exercise E should know which corpus carries
  edges; the J-phase slope item needs a corpus with shared worktrees.
- F-clock-wall (browser). In-page clock stats match counts (0 commits,
  contained re-runs) but actionMs reads ~1.7s p50 under load 10–12.5
  with 0 longTasks — frame starvation and engine re-run cost are
  inseparable here. Withheld; POD-4489 re-runs and separates them.
- F3 (harness, G4 — confirms hand-M2 F3). Browser commit logging never
  worked on any arm; needs a G4 follow-up before J-phase walls.
