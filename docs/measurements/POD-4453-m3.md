# POD-4453 M3 — hand-rolled arm: lifecycle, growth, coexistence, write sketch

Issue: J1 hand-rolled arm, milestone 3 (`POD-4453`). Arm change since M2: the
deferred slope item is removed — rollup `openExplicit` / `lastActive` /
`staffed` seats are maintained incrementally instead of rebuilt per computing
dispatch — plus arm-local computation-share timing (`HandStats`,
`store.phaseMs()`). No shared/ or harness/ change.

Seed status, read first: the count tables below were measured on the pre-4491
seed (counts are load-independent; box load 6–10 through the runs). After the
rebase onto 4491's `815e2e85f` the 1x mount parity fails exactly as the
coordinator announced (extra row in one group, byte-identical across arms);
that verdict belongs to POD-4496 and is not chased here. The mechanism result
(batch removal with identical derivations) is seed-independent: the M2 strict
gate passed with byte-identical rows/derivations before the rebase.

JSON: `hand-m3-summary.json` (attached to the issue; `harness/browser/results/`
is gitignored). All browser walls withheld for POD-4489 (timing owner); counts
carry the verdict meanwhile.

## 5. Stats split (methodology §6.4)

Count split per event (load-independent): #2/#5 = 1 committed row + 3
derivation bodies + 0 bucket writes → row assembly 25%, rollup 75%, index 0%;
#1 = 0/0/0 (nothing runs); burst reference (M2 #10): 32 rows + 143 bodies +
50 bucket writes. Timed split (`phaseMs`, happy-dom, load-contaminated proxy):

| Step | 1x index / rollup / row (ms) | 4x index / rollup / row (ms) |
|---|---|---|
| #1 | 0.38 / 1.05 / 0.26 | 0.02 / 0.18 / 0.01 |
| #2 | 0.03 / 1.00 / 0.33 | 0.02 / 0.23 / 0.05 |
| #5 | 0.06 / 0.70 / 0.13 | 0.07 / 0.30 / 0.11 |

Rollup-dominated (~60–80% of the timed levels) at both scales; the absolute
milliseconds are box-load noise, the event pipeline is sub-millisecond in
happy-dom either way. If rollups dominate at 4x in the browser too,
server-side projections are the next lever — the leased re-run will say with
real numbers.
