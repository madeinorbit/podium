# POD-4746: the work-per-change check — cells, plants, old vs new

The check (`packages/worklist-proto/harness/src/scale-check.ts`, run by
`work-per-change.test.tsx`; described in `docs/plans/pod-4441-harness.md`,
"Work per change"): every fence scenario #1–#10 on a 1x engine and a 4x engine,
work counted from outside the arm, and for each scenario and count

    count at 4x − count at 1x ≤ the changed items' neighbourhood at 4x

Counts: **rows** (distinct rows whose data the arm read), **derivations**
(MobX computed and reaction bodies run), **elements** (distinct collection
elements the arm walked). Neighbourhood: the changed items' families, plus the
sections a moved row leaves and enters, read off the store and the oracle's
order; nothing typed in.

Provenance: flatblock, `bun run test:file`, counts only (no walls, so load
gates nothing), 2026-09-28, branch `issue/4746-work-per-change-check` on
integrate/4545-round-three; cells from the run at `f60180e2f` rebased onto `98d7d5776`.
Corpus `buildCorpus(scale, FIXTURE_SEED)`: 1x 4,867 issues / 732 visible rows,
4x 19,468 / 2,928. The raw cells are `harness/browser/results/work-mobx.json`
and `work-control.json` (git-ignored).

## 4. Instrument self-checks

- `work-meter.test.ts`: each kind of walk counts its elements; repeated walks
  count once, `visits` keeps the repeats; the arm's side follows awaits and
  timers and the other side counts nothing; MobX derivations count and their
  walks are theirs; every patch is restored.
- `neighbourhood.test.ts`: a session stands for its issue's family; a row that
  keeps its place adds no section; a moved row adds the sections it leaves and
  enters; a section moving among sections moves its rows.
- `reads.test.ts`: `data` counts field reads and per-row feed reads, not ids
  from table walks or relations; an adapter's in-place table counts as data;
  the copy sweep sees an arm that stores borrowed rows with no wrapped table.

The hand-rolled arm is paused: its cells are added when it resumes.
