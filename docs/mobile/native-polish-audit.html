Podium mobile · teardown & fix · POD-366

Shipped

It read like a website
because it still was one.

Your colleague was right, and the reason was more specific — and more fixable — than “the design needs work.” The design is good. What was missing was three things that have nothing to do with taste: the app was never installed, touch had no physics, and the whole interface was set at desktop density. All three are now fixed, along with nine smaller findings.

Expo 57 · RN 0.86 · expo-router 11,790 LOC audited iPhone 14 Pro viewport 51 files changed

Nothing here needs a redesign. Podium mobile already has a real design system — the Superade tokens, the carved tiers, the one-yellow-signal rule — and the screens are thoughtfully composed. The gap between it and a native app is almost entirely made of platform behaviours it never opted into.

The clearest proof: the codebase contains a component called PressableScale, whose own docstring reads “Use for every card/button — consistent physical feedback is most of what makes a UI feel native.” It is imported in 4 files. Twenty other files that handle touch use a bare Pressable. The team already knew the answer and it never got wired up.

The diagnosis

Three layers, in the order they hurt

Each layer is independently fixable, and they are listed by how much perceived “nativeness” you buy per hour spent. The first one is a day of work.

LAYER 1

The app was never installed

The shipped dist/index.html had no web manifest, no apple-mobile-web-app-capable, no theme-color, and no apple-touch-icon — verified in the live build. Add to Home Screen produced a Safari bookmark: browser chrome pinned to the top, the address bar eating ~100 px of a phone screen, and a cropped screenshot for an icon. No amount of work inside the app compensates for a frame that announces “this is a web page.”

Done · manifest, icons, 9 launch images, navy first paint

LAYER 2

Touch has no physics

Press feedback existed as a component and was used in 4 of 24 touch-handling files. Haptics fired in 3 places in the entire app. Long-pressing a card pops iOS’s text-selection magnifier (user-select is left at auto). Safari rubber-bands the page behind an app that cannot scroll (overscroll-behavior: auto). The action sheet draws a drag handle it does not respond to. Going back calls router.replace(), so there is no interactive edge-swipe and no pop animation. Tapping the tab you are already on does nothing — on iOS that scrolls to top.

Done · 4 → 24 files · no new dependencies were needed

LAYER 3

It is set at desktop density

Measured across apps/mobile/src: 34 distinct fontSize expressions. The most-used size is 12 px (48 occurrences). The largest body size in the app is 13 px. For reference, iOS body text is 17 px and its smallest standard style is 11 px. The team already hit the consequence and patched around it — the build script injects maximum-scale=1 with the comment “iOS Safari auto-zooms any focused input under 16px — the app’s dense type is 12–13px.” That patch is the symptom.

Done · 34 expressions → 7 tokens · the viewport hack is gone with them

Findings

Twelve specific things, ranked

Ordered by perceived impact per hour of work. All twelve are shipped in the browser build — none of them needed a native app.

01

There is no PWA manifest

highest impactweb

Confirmed against the running build: no link[rel=manifest], no apple-mobile-web-app-capable, no theme-color, no apple-touch-icon. Home-screen launch keeps Safari’s chrome.

ShippedExtend scripts/patch-web-html.ts to inject a manifest link, apple-mobile-web-app-capable=yes, status-bar-style=black-translucent, theme-color=#0a0f1c, and a 180 px apple-touch-icon. Ship manifest.webmanifest with display: standalone and the existing app icon at 192/512. Add an iOS splash so cold start isn’t a white flash.

02

Press feedback is built but not used

highest impactweb

PressableScale — spring scale-down plus a light haptic — is imported by Composer, SessionCard and InboxScreen. The Tray cards, Work rows, Tasks rows, tab bar, every header button and the action sheet use a raw Pressable, most with no pressed state at all.

ShippedSwap Pressable for PressableScale across the 20 remaining files. Mechanical, high-yield, and it is what the component was written for.

03

Body text is 4 px below every other iPhone app

highest impactweb

34 distinct fontSize expressions; most-used value 12 px; largest body 13 px. Off-scale one-offs (11.5, 10.5, 9.5, font.small - 0.5, font.micro + 0.5) undercut the token scale that already exists in theme.ts.

ShippedRe-base the scale: body 17, secondary 15, caption 13, micro 11. Delete the arithmetic variants. Then remove maximum-scale=1 from the viewport patch — it exists only to suppress the input auto-zoom that sub-16 px fields cause, and it currently costs pinch-zoom accessibility for nothing.

04

Empty states double as loading states

web

One screen in twelve (ProposalScreeningScreen) shows a spinner. Everywhere else an empty list paints “No tasks” the instant the screen mounts, then content pops in a moment later. That flicker is read as breakage, not latency.

ShippedThree skeleton rows on first load per list; keep the empty state for genuinely-empty. Never show an empty state before the first response has landed.

05

No pull-to-refresh anywhere

web

RefreshControl appears zero times in the codebase. It is the first gesture a phone user tries on a list, and its absence reads as “this screen is stale and I can’t do anything about it” — even though the data is live over a socket.

ShippedAdd RefreshControl to Tray, Work, Tasks and Sessions. Even when it only re-syncs an already-current replica, the gesture is the reassurance.

06

Long-press pops the text-selection magnifier

web

user-select is auto and overscroll-behavior is auto on the document. So holding a card selects its text and offers “Copy / Look Up / Share”, and dragging past the end rubber-bands the page behind an app whose root is overflow: hidden. Both are pure browser tells.

ShippedIn the HTML patch: user-select: none on the root with text re-enabled on transcript and markdown content only, plus overscroll-behavior: none and -webkit-touch-callout: none.

07

The session header carries six controls

web

Back chevron, ID square, two-line title, “Next”, a Chat / >_ segmented control, and a kebab — inside a 44 px bar on a 390 pt screen. Tap targets end up adjacent and under-sized, and the yellow “Next” competes with the yellow that means “this needs you”.

ShippedBack + title + one trailing kebab. Move the Chat/terminal switch to a segmented control on its own row under the header, and “Next” into the menu.

08

The yellow signal is spent in five places per screen

web

The design system’s own Signal Rule reserves #f5c518 for “waiting on you”. In practice it also paints Tray timestamps, the “Show done” toggle, the session header’s “Next”, the recap divider and the active tab. When everything is the signal, nothing is.

ShippedAudit every yellow. Timestamps and toggles go to --dim; keep yellow for the needs-you badge, the primary action, and the active tab.

09

Forms push as pages, not sheets

web

New Session, New Issue and Settings are plain stack pushes — no presentation: 'modal' is set anywhere in app/. On iOS a create-form is a sheet you can swipe down to abandon; a push implies you are going somewhere and have to come back.

Shippedpresentation: 'modal' on those three routes, with a Cancel/Save bar instead of a back chevron.

10

The action sheet draws a handle it ignores

web

ActionSheet renders the 36×4 drag pill that on every native sheet means “drag me down”, and has no gesture attached. It also cannot be swiped to dismiss. Signalling an affordance and not honouring it is worse than omitting it.

ShippedAdd react-native-gesture-handler and drive dismissal from a pan, or drop the handle. Same choice for the tab bar: tapping the focused tab should scroll to top and pop to root, and currently returns early.

11

Markdown tables run off the screen edge

web

Visible in the session capture: a three-column table is clipped mid-word at the viewport edge with no horizontal scroll and no indication that content continues. Agent replies contain tables constantly, so this is not an edge case.

ShippedWrap tables in a horizontally-scrollable view with a fade mask on the cut edge, or collapse to stacked key/value rows below ~400 pt.

12

The spinner re-renders 12 times a second, forever

web

BrailleSpinner drives a setInterval at 80 ms into React state — one timer per visible working session, each triggering a component re-render on the JS thread. It is also the only motion in the app: three components total import Animated, and react-native-reanimated is not a dependency, so nothing can animate off the JS thread. Separately, expo-blur is installed and used zero times.

ShippedMove the spinner to a native-driver loop or a single shared clock. Add reanimated and use it for the pressed states, sheet, and list transitions. Put the already-installed BlurView under the tab bar and the composer — translucent chrome is one of the strongest native cues on iOS.

Corrections

Three things the audit got wrong

Found while implementing. Two were real defects with the wrong cause named, and one was not a defect at all.

Markdown tables were already scrollable

The audit said they ran off the edge “with no horizontal scroll”. MarkdownTable has always wrapped its rows in a horizontal ScrollView. What was missing was any sign of it — on touch, the scrollbar stays hidden until you drag, so the table simply appeared clipped mid-word. The shipped fix is the fade on the cut edge, not a scroller.

The Super Agent “void” is a deliberate decision

The transcript sets justifyContent: 'flex-end' with a comment citing POD-338: a short conversation rests on the composer instead of hanging from the header, matching the desktop chat. That is how iMessage behaves too. Left alone. The same goes for the Tray’s empty lower half — a two-item list has empty space below it on iOS as well, and the audit overstated it.

The tab bar deliberately does not float, so it does not blur

Finding 12 proposed putting the unused BlurView under the tab bar. But TabBar’s own docstring records replacing a floating glass pill with a carved in-flow bar under DESIGN.md’s “carved not floating” rule — and nothing scrolls under an in-flow bar, so blur there would be decoration over a documented decision. The blur went to the composer instead, where native previously had none at all.

What landed

Tiers 1 and 2, in one pass

Tier 1 — the install and the density

shipped · web build
  1. Manifest, icons, standalone, navy launch — nine per-device launch images so no iPhone falls back to a white flash.
  2. PressableScale everywhere — 4 files to 24, plus Reduce Motion support.
  3. Browser tells off — selection, callout menu and rubber-band, with prose opting back in.
  4. Type scale re-based to 17 / 15 / 13 / 11, line heights derived, maximum-scale=1 deleted.
  5. Skeletons before the first snapshot, empty states only when genuinely empty.
  6. Pull-to-refresh that forces the socket to retry now instead of waiting out backoff.

Tier 2 — the manners

shipped · web build
  1. Create forms and settings present as sheets, with Cancel instead of a back chevron.
  2. The action sheet answers the drag its handle was already advertising; re-tapping the active tab scrolls to top.
  3. Session header: one trailing control instead of six, view switch on its own row.
  4. Yellow spent only on what needs you — timestamps and the done-filter gave it up.
  5. Table edge fade; the spinners share one clock; the composer gets real blur on native.

Still open

not started

Two things a browser cannot do, both parked with the native path in POD-368: push notifications when an agent needs you, and a live socket that survives backgrounding. Everything else on the list is done.

In one line

The mobile app didn’t need to be redesigned. It needed to be told it’s an app — installed, physical to the touch, and set at a size a phone expects. It is now all three.
