Ghost-preview empty states

The four surfaces from ADE Empty States.dc.html, as implemented. Each empty surface draws a dimmed, dead copy of its own content, fading out downward, under one line of live copy — the shape of what is coming, not a spinner.

POD-1058 · branch issue/1058-empty-states · both Superade themes

What this page is. A token-accurate reconstruction, not a screenshot: it declares the same --ghost-1..4 ramp and the same Superade palette the app resolves, at the same geometry and with the same copy, so both themes can be judged side by side without standing up a runtime with an empty repo. The shipped markup is in the four components named under each state. It is not a live capture of the running app.
Rebased onto the 3a sidebar. POD-1057's redraw landed on main mid-flight and changed the rows the work-list ghost mirrors — 44px at a 13px inset, a 26px id gutter, a fixed 56px meta column, section labels promoted to folding bands, and no rules between rows. State 1 below is drawn against that, not the row it was designed on. The other three surfaces were untouched by 3a.

1 · Work list — ghost rows

apps/web/src/features/worklist/WorkListEmpty.tsx

Four ghost rows at the live row's own anatomy — the 3a row this landed against (POD-1057): a 26px id gutter, title and a fixed 56px meta column on line 1, a mono status line on line 2, 44px minimum, no rules between rows. Those numbers are imported from WorkRowShell's own ID_GUTTER_W and META_COL_W rather than copied, so the next retune carries the ghost with it. Above them sits a static section band: on an empty list it is the only thing saying which project is empty, which is what kills the “is this loading, or am I pointed at the wrong repo?” doubt. Its 0 is rendered where a live band hides it — the cheapest proof the bars are not data.

2 · Flight deck — ghost tree

apps/web/src/app/FlightDeck.tsx → EmptyDeck

A tree, not a stream: two task strips with sessions hanging under the deck's real rail, and a last strip whose id chip is dashed — that one stands for a proposed task. The two coloured session dots are the fastest way to say this pane is a status readout; they take the semantic status tokens only, never an issue colour. No button and no header title — the work list and the composer own both ways in, and there is no session to name yet.

3 · Task explorer — right dock

apps/web/src/features/issues/explorer/IssueExplorerList.tsx → GhostRows

The real search field and the real stage tabs stay, at their honest 0. The stages are the mental model of this pane and two lines of prose cannot teach them, so the strip earns its space even empty. Search stays enabled — typing a ref is how people arrive here — and only the promise of a count leaves the placeholder. Which tab looks selected is still defaultTab()'s call, unchanged.

4 · Tab area — nothing open in the pane

apps/web/src/app/Workspace.tsx → Empty, GhostTabs

A tab is a view, and the copy says so: closing one closes the view and never touches the session. The button is the ＋ menu under the menu's own title, “New panel”, because it opens a menu rather than silently making a tab; the footnote lists what the menu offers. No shortcut is claimed — nothing registers one. The two ghost tabs carry a status dot and a file glyph so the strip teaches that both kinds live there. These alone are not faded: at 28px in a 38px strip a vertical mask reads as a bug.

The ramp

One ramp serves every surface. The tiers are mixes over transparent, not flat values, so the same four steps work over the work list, the deck and the dock — three different tones — without retuning. Light takes a heavier dose than dark for the same apparent step, because dark ink on stone loses contrast faster than light ink on near-black.

What to look at

  • Nothing moves. No shimmer, no pulse, anywhere. Motion is what makes a reader classify bars as loading and then wait for something that will never arrive.
  • Everything fades. Each block ends in a bottom mask, never a hard cut — a hard cut reads as a list that got truncated.
  • The honest zeros. WORK IN <project> 0 and the seven stage counts stay live beside the ghosts.
  • Both themes from one definition. Every value above is a token; nothing is a hard-coded hex in the components.

Two behaviour changes

  • An empty pane now chooses its state from what there is to adopt, not from whether it is alone. The picker is strictly better when another pane holds tabs; the old test drew a “Pick a panel” heading over no choices for the empty half of a split whose sibling was also empty.
  • useDefaultSpawn gained bindChord. The work list's empty-state button fires the same spawn as the row above it, and two mounted owners of the ⌘N binding would have spawned two agents from one press.

Open

  • The deck's empty state has no model icon in its header, where the mock draws one. There is no session yet, so the icon could only name a default agent — an invented identity on the one surface whose whole job is honest status. Easy to add if the intent was “which agent would run”.
  • Filtered-to-empty states are untouched, as the design notes flag: a search with no hits and a stage tab at 0 while others have rows keep their existing words. “No match” must never get the same copy as “nothing exists yet”, and never a CTA.
  • The centre composer in the same design file belongs to POD-780 and is untouched.
