POD-1174 · Concept

First run, and nothing else

Until Podium is set up, setup is the only thing on screen. One question per screen, two answers each, and no way to wander off before there is anything to wander into.

Web shell · activation 2 new screens 1 escape hatch removed For review
01

The shell steps back

Today onboarding sits inside the live app: work sidebar on the left, Flight Deck beside it, dock and rail on the right, status strip along the bottom, mode tabs and readouts in the header. All of it points at a product that has nothing in it yet.

While setup is unfinished, none of it renders. The window keeps its bar — it is the drag handle and, off macOS, it carries the window buttons — but the bar is empty. Everything else is the setup screen.

  • GoneWork sidebar, Flight Deck, right dock, right rail, status strip, mode tabs, host and quota readouts, Settings and Usage buttons.
  • KeptThe window bar itself, empty, so the window can still be dragged, minimised and closed.
  • AfterThe moment setup completes, the full shell comes back exactly as it is today.
02

Two answers per screen

The first screen asks where Podium runs. The VPS answer then asks one more question — new server, or one you already have — which is the fork that used to be a third option on the first screen, where it confused people who had nothing to connect to yet.

Screen one — where Podium runs

Set up Podium

Where should Podium run?

Podium keeps your agents working. Pick the computer it lives on — you can move it later.

You can add machines or move Podium later. This is not a one-way door.

  • GoneThe Explore Podium button and the line under it. There is nothing to explore before a project exists, and it let people land in an empty app and call it broken.
  • NewThe whole card is the target, so the label never has to repeat the heading. Bigger hit area, one tab stop each.
  • CopyPlain second person, no jargon: “Podium runs on this computer”, not “all-in-one topology”.

06

What comes out

  • GoneExplore Podium. Removed from every setup screen — the first screen, the SSH install screen, both connect screens, agents and first task.
  • GoneThe “Activation paused · Resume” bar. Nothing can pause setup any more, so nothing needs resuming.
  • GoneExploring mode and its activationMode=exploring URL state. Setup still remembers which step you were on across a reload; it just has no “away” state to come back from.
  • KeptEvery saved draft — the typed server URL, the picked repositories, the first task text — still survives a reload, as it does today.
  • KeptLogin and server-unreachable screens are untouched. They sit outside setup and already own the whole window.
07

Two calls worth confirming

An empty window bar, or no bar at all

Proposed: keep the bar, empty, because it is the drag region and holds the minimise, maximise and close buttons on Windows and Linux. The alternative is no bar during setup, which on those platforms leaves the window without controls.

Named steps instead of “1 of 3”

The counter cannot survive a fork — the local path and the VPS path are different lengths. Proposed: name each step in the eyebrow. If you want progress shown, the alternative is a count that only starts after the fork, on the local path.
