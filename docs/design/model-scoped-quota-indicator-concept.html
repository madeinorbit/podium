The gate and the fallback: two quotas, one indicator

Claude Code reports limits of two different kinds. Some gate all work — spend them and nothing runs. Others are scoped to a single model — spend them and the harness simply falls back. Today the summary takes the worst of both, so a spent Fable bucket paints the whole meter red while the limits that actually gate work sit at 7% and 54%.

Two kinds of limit, one flat list

Unscoped limits gate the harness: at 100% nothing runs. A model-scoped limit is extra capacity for one model — spent, Claude Code falls back to the models the unscoped pool still covers. The UI has been treating them as interchangeable.

Proposed: the gate meter keeps its meaning, the fallback gets its own rail

The existing 25×3.5 pool meter now answers exactly one question — can I work, and for how long — driven by the unscoped limits alone. A 2px rail sits under it, one segment per model-scoped bucket, filling and toning independently. Both quotas, one indicator, no new control in the header.

Why the rail, and not a redder bar

Tone must answer one question. The gate meter's color says whether work can proceed. A model bucket cannot change that answer, so it must not change that color — otherwise every red loses its meaning.

The loss is still real. Fable being gone changes which model you get, so it earns its own mark: a red segment on the rail, and a named verdict in the panel. The signal is present, scoped, and unmistakable.

Nothing new for single-quota harnesses. The rail only exists when the provider reports a scoped bucket. Codex, and Claude Code on a plan without one, render exactly as they do today — same pixels.

The summary never claims to be spent unless the limits that gate work are spent. A scoped model reports itself, by name, and never for the account.
