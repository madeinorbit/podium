POD-1077 · proposal · reconstruction, not a capture

Shell context menu actions

What belongs in the menu for a mission, a sub-task, a session, and a tab — and why three of today's session verbs are the same act under different names.

Reads against POD-1074's vocabulary.

The issue menus below use POD-1074's names, not main's: its Set status submenu replaces Set stage plus the two Close (…) rows, and wontfix is now Cancelled with Duplicate as its own ending. That branch (issue/1074-cancelled-duplicate-states, tip 43e020450) is in review and not yet on main, so the line numbers cited throughout are main's while the labels are POD-1074's. Nothing proposed here changes Set status itself — the two sets of changes touch different rows of the same menu and can land in either order.

What's actually wrong

1 · “Close” means two different things, one menu apart.

On the tab menu, Close closes a view and never touches the agent (Workspace.tsx:1036). On the session menu, Close calls guardedKill → killSession, which writes a durable tombstone and removes the row (session-kill.ts:1) — terminal, no restore. Same word, same ✕ glyph, two controls a few pixels apart on the same session. This is the highest-severity item on the surface.

2 · Session “Archive” does not archive. It stops the agent.

POD-108 made archive park the process — parkArchivedSession sets the session to hibernated or exited and kills it (session-teardown.ts:105). The guard even says so out loud: “this agent is still working — archiving it now ends its turn” (use-session-guard.ts:73). The word promises filing; the action ends work.

3 · The instinct “it's the issue that gets archived” is already the backend model.

Archiving an issue cascades to its member sessions (#133, relay.archive-cascade.test.ts), and a sweep auto-archives sessions that are stopped and read ([spec:SP-6144], tryAutoArchiveStoppedObserved). Session-level archive is a manual duplicate of two paths that already run on their own.

4 · The verb the operator actually wants is built and unexposed.

sessions.stop [spec:SP-9904] — stop the process, free the worktree when safe, keep branch, transcript and row, resume recreates the worktree from the branch — is live on the command plane (command-plane.ts:631) and wired to the CLI (session-cli.ts:305). It has zero call sites in apps/web. Meanwhile the command palette aliases the keywords stop and end session onto the tombstoning kill (CommandPalette.tsx:528), so searching for the safe verb hands you the terminal one.

5 · A mission and a sub-task get literally the same menu.

The flight deck imports IssueContextMenu with surface="sidebar" (POD-771, “imported, never forked” — FlightDeck.tsx:2830). Only the colour row differs, gated top-level by [spec:SP-b4d1]. So a sub-task still offers Archive and Pin, which are both mission-scoped ideas.

6 · Delete shares a block with Pin.

The tree is sectioned main / lifecycle (“LIFECYCLE”) / destructive (“MANAGE”). That split is sound — but MANAGE then holds Pin, Archive, Duplicate of, Restore and Delete in one run (issue-menu-config.ts:352–399), so the terminal action sits directly under a bookmark toggle with no rule above it, distinguished only by red ink. The section the code calls destructive is mostly not.

7 · You cannot rename a task from the flight deck.

FlightDeck.tsx:2830 mounts IssueContextMenu without an onRename prop, and the entry is gated on renameEnabled (issue-menu-config.ts:166) — so Rename is silently absent from every strip and from the mission header, while the sidebar and the board both have it. The deck is the column the operator actually works in.

8 · Closing confirms on one surface and fires instantly on two others.

With onRequestClose supplied (IssueCompactControls) closing opens IssueCloseDialog; without it — the sidebar and the flight deck — it calls closeIssue straight through (IssueContextMenu.tsx:231). One verb, two levels of ceremony, decided by which surface you happened to right-click. POD-1074 does not fix this — its close() keeps the same fork (IssueContextMenu.tsx:232 on that branch), so picking Done, Cancelled or Duplicate from Set status inherits the split rather than resolving it. Confirmed with that issue's agent: the fork predates it, so they corrected their artifact and filed it as a spin-off rather than widening scope. It belongs to neither this sheet nor POD-1074 — listed here only so the inconsistency is not lost.

The rule to adopt

One noun per menu, and the verb names what survives. A session has four real server-side ends. Today the UI offers the two extremes and skips the useful middle — then calls the terminal one “Close”.

verbprocessworktreerow + transcriptway backin web today
Hibernateparkedkeptvisible Resumeyes
End (sessions.stop) killedfreed when safevisible Resume — rebuilds the worktree from the branchno — CLI only
Archiveparkedkepthidden Unarchive (does not resurrect)yes
Delete (today: “Close”) killed—tombstoned noneyes, mislabelled

Hibernate / End / Archive / Delete are four distinct outcomes. Hibernate, Archive and Close are today's three labels — and two of them park a process while the third destroys a record.

The three changes

Add “End session” → sessions.stop. This is the everyday “I'm done with this agent”: the process stops, the worktree frees, the transcript stays, Resume brings it back. It is the missing verb, and it already exists.

Rename “Close” → “Delete session…”, behind a rule, and confirm always rather than only while working — the current guard fires on a working agent only, so deleting an idle session's whole record is a single unconfirmed click. The ellipsis states that a confirm follows.

Drop “Archive” from the session menu. Issue archive cascades (#133) and the sweep handles the tail; keeping it means a third synonym for “stop the agent”. Leave Unarchive rendered only when the subject is already archived, so the state stays escapable. Softer variant if you'd rather not lose it: keep it but move it under the rule beside End, since that is what it does.

That decision is right and I'd keep it — a killer one slip below “Close All” is a bad trade. Substantially right, and the LIFECYCLE / MANAGE split already works. Archive belongs here and should stay: this is the user-facing “put it away”, and it already cascades to sub-tasks and sessions. Three fixes, all small.

Note on the affordance: the sidebar is right-click only — there is no ⋯ button on a mission row. The ⋯ exists on the deck strip and in IssueCompactControls. That asymmetry is defensible (the deck's comment at FlightDeck.tsx:1101 says the sidebar teaches the gesture and the ⋯ is the deck's discovery affordance) — but it does mean a first-time operator has no visible way into the mission menu at all.

Set status ▸ is POD-1074's list, unchanged by anything here — three categories separated by two rules, because Completed and Cancelled are separate outcomes the way Linear keeps them: Backlog / Planning / In Progress / Review · Done · Cancelled / Duplicate. Entries carry an outcome and each surface draws a rule wherever it changes (issueStatusMenuEntries). This sheet does not touch that submenu; it is shown so the surrounding blocks read correctly.

Put a rule above Delete and let it stand alone below MANAGE. It's two lines of config — give the destructive section a fourth value that actually means it — and it's the cheapest safety change on the whole surface.

State the cascade in the Archive confirm. It already warns when childCount > 0, but with a bare count-free sentence — and it uses a raw window.confirm (IssueContextMenu.tsx:351) while every other guard in the app uses useConfirm. Name the numbers: sub-tasks and the agents that will be stopped, because that second half is invisible today.

One ceremony per verb. Closing opens IssueCloseDialog from IssueCompactControls and fires instantly from the sidebar and the deck (finding 8) — and POD-1074 carries that fork forward unchanged. The fix is to wire onRequestClose everywhere so a terminal status always offers the same dialog. It is already filed as a spin-off off POD-1074, so it is not in this issue's work order below — noted here to close the loop on the finding.

Pass onRename. The deck strip already has an inline editor pattern — the session row uses one (FlightDeck.tsx:1132). This is the one item the deck is missing outright rather than carrying wrongly.

Drop Archive. Archiving one sub-task out of a mission punches a hole in the spine that the deck cannot show and cannot restore from — there is no archived filter in that column. Closing it is the honest gesture; archiving belongs to the mission that owns the whole subtree.

Drop Pin. Pinning orders the sidebar's mission list; the deck orders by the spine, so the row does nothing you can observe from here.

Promote placement to its own named block. “Move to top level” is the most characteristic decision a sub-task has — it's the spin-off gesture — and today it sits unlabelled mid-menu. Header it PLACEMENT and it stops reading as another lifecycle row.

Colour is already correctly absent here — [spec:SP-b4d1], the colour names the mission and a sub-task inherits it.
