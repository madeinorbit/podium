The Closed Fold — archive without the chore

Tillmann's real workflow ends with typing "close and archive" — because close alone leaves the row shouting in the sidebar, and only archive quiets it. That's a chore standing in for a missing visual state. The fix: closed issues fold themselves. Archive stops being a command and becomes gravity.

Provenance

POD-100's Proposal B had Law 06, "Done decays": settled completion collapses into a one-line › Done · N strip. Round-3 decision 15 killed it — correctly — for done children: done is a stage, not an exit, and children got the shipped decay instead. That decision stands untouched. This concept re-homes the fold one level up, where it was always right: closed, top-level issues. Closed is an exit. Exits can fold.

F1

Closed folds, done doesn't

The fold only ever contains closed issues. Done stays a full row with shipped decay, exactly per POD-100 decision 15. No conflict, no regression.

F2

Unread resists folding

A closed issue whose result you haven't seen keeps its row — full opacity, blue beacon — no matter how old. Nothing folds until it has been read.

F3

The fold is quiet

One faint mono line, › Closed · N, hairline rule to the edge. It never carries attention states — anything demanding attention is, by F2, not in it.

F4

Archive becomes gravity

Rows inside the fold auto-archive after a grace window (proposal: 14 days). Manual archive still exists for "get it out now" — but nobody has to type it anymore.

Row grammar (tint-never-fill, idsq chips, static unread dot, calm-blue working spinner) is taken verbatim from the approved POD-100 final artifact. Nothing here introduces new vocabulary — only a new destination.
