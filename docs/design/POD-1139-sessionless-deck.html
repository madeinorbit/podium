The deck with no mission in it

The flight deck has three ways to have nothing to show, and until now they shared one screen written for the rarest of them. This splits them: a load draws a ghost and says nothing, a shell is told what it is, and a session that simply has no task gets the empty deck that already says the right sentence.

POD-1139 · apps/web/src/app/FlightDeck.tsx · both Superade themes

What this page is. A token-accurate reconstruction, not a screenshot — the same --ghost-1..4 ramp, palette, geometry and copy the components resolve, so both themes can be judged side by side. Two of the three states are hard to photograph honestly: the settling ghost is a few hundred milliseconds long, and the shell state needs a shell in pane A. It is not a live capture.

What was there — one screen for three facts

removed: FlightDeck.tsx → IntakeCanvas

Shown to every focused session the deck could not root: a spawn mid-settle, a panel-menu agent, a resumed conversation, and a bash shell. It named the session, then printed Task / Plan / Team placeholders — the same three rows the right dock's IntakeDock was printing in the other column at the same moment — and closed with a line of philosophy. For the common case it was on screen for about as long as it takes to read the heading.

1 · The mission is still arriving — a ghost, and no words

FlightDeck.tsx → SettlingDeck · focusedSession.issueId set, no root yet

The composer's spawn paints the draft vessel and the session together, so the session already knows its task and only the selection is behind. That gap is a load, so it draws the shape that is about to arrive and writes nothing: one task strip with one session under the tree's own rail. Not EmptyDeck's four rows — that ghost teaches the shape of the pane to someone who has never loaded it, while this one stands in for a specific tree exactly one strip deep, and a ghost that collapses on resolve reads worse than no ghost at all.

2 · A shell — its own words, never the agent's

FlightDeck.tsx → ShellDeck · agentKind === 'shell'

“New Shell” in the panel menu creates a session with no task and no draft vessel, and it lands in pane A like anything else — so this is durable, not a flash. It used to be told that “the agent will organize this workspace as you talk”, over a bash prompt that will do nothing of the kind. It now takes the shape standbyCopy already uses for the same case (“A shell keeps no transcript”): state the limit, then point at where the answer is. The ghost stays, because the column is still a task tree and picking one is what fills it.

3 · A session on no task at all — the empty deck, unchanged

FlightDeck.tsx → EmptyDeck · no issueId, or nothing focused

A panel-menu agent and every resume arrive with no vessel and will not grow one on their own. “Pick a task on the left or start a new one” is not first-run advice for them — it is the whole answer, and it is already written here. So this state stopped having a screen of its own. Nothing about this surface changed; it just covers one more case.

What to look at

  • The settling column is empty of text on purpose. Whatever is written there is a sentence the operator watches get taken away a beat later. The test asserts its textContent is the empty string, so a future line cannot creep back in unnoticed.
  • The shell heading is a statement, not an invitation. It is the one state here that is not going anywhere, so it is the one that gets a heading at all.
  • Nothing moves, everything fades. Both ghosts obey POD-1058's rules — no shimmer, bottom mask rather than a hard cut, and the session dot is the only hue.
  • One duplicate is gone. The right dock's IntakeDock keeps its Task / Plan / Team rows; the deck no longer prints a second copy of them in the other column at the same moment.
